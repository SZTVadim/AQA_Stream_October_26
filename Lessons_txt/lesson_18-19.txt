Слайд 1 — ООП в Python

ООП в Python — это подход к программированию, который позволяет создавать свои типы данных.
Мы можем описать, как эти типы должны работать, и потом создавать объекты по этому описанию.

Вместо того чтобы писать отдельные функции, мы создаем классы — это шаблоны для создания объектов.

В тестировании классы очень полезны:
- можно создать класс для тестовых пользователей (например, User)
- можно организовать утилиты для работы с API или базой данных
- код становится более структурированным и его можно использовать повторно

Слайд 2 — Что такое ООП простыми словами

ООП — это способ писать программы, где всё состоит из объектов.
Объекты создаются по классам — это как шаблоны или инструкции.

Чтобы было понятнее, представьте конструктор LEGO:
- Класс — это инструкция, как собрать деталь
- Объект — это уже собранная деталь по этой инструкции

Например, если есть инструкция «Машинка», по ней можно собрать много разных машинок.
Все они будут одного типа (класса), но у каждой будут свои особенности — разный цвет, размер и так далее.

В тестировании это означает: один класс TestUser может создать множество разных тестовых пользователей.
У каждого будут свои имя, email и пароль, но все они созданы по одному шаблону.

Слайд 3 — Основные принципы ООП

В ООП есть четыре главных принципа, которые помогают правильно организовать код:

Инкапсуляция — мы прячем внутреннее устройство объекта и показываем только то, что нужно для работы.
Представьте коробку с кнопками: вы знаете, как её использовать, но не видите, что происходит внутри.
В тестах это помогает скрыть сложную логику и дать простые методы для работы.

Наследование — можно создать новый класс на основе существующего, взяв все его возможности и добавив свои.
Это похоже на семью: дети наследуют черты родителей, но у них есть и свои особенности.
Например, класс AdminUser может наследоваться от User и добавлять методы для администрирования.

Полиморфизм — разные объекты могут выполнять одинаковые действия, но каждый делает это по-своему.
Это как один пульт, который может управлять разными устройствами.
В тестах это позволяет писать универсальный код, который работает с разными объектами одинаково.

Абстракция — мы выделяем только самое важное, убирая лишние детали.
Это как упрощенная схема, где показаны только ключевые элементы.
В тестах это помогает создать общий интерфейс для группы похожих классов.

Слайд 4 — Абстракция в ООП

Абстракция — это принцип, когда мы выделяем самое важное и скрываем всё остальное.
Абстрактный класс определяет, какие методы должны быть у классов-потомков, но не говорит, как именно их реализовывать.
Это как договор: "Ты должен уметь это делать, но как именно — решай сам".

Зачем нужна абстракция в тестировании:
- создать общий способ работы для группы классов (например, все классы для работы с базами данных должны иметь метод connect())
- убедиться, что все классы-потомки обязательно реализуют нужные методы
- скрыть внутреннюю реализацию от того, кто использует класс

Слайд 5 — Абстрактный метод

Абстрактный метод — это метод, у которого нет реализации (кода внутри).
Он нужен для того, чтобы обязать все классы-потомки написать свою версию этого метода.

В Python для работы с абстракцией используется модуль abc:
- ABC (Abstract Base Class) — это специальный класс, от которого наследуются абстрактные классы
- @abstractmethod — это декоратор, который помечает метод как абстрактный и требует его обязательной реализации в потомках

Пример:
    from abc import ABC, abstractmethod

    class Animal(ABC):
        @abstractmethod
        def make_sound(self):
            pass

Слайд 6 — Пример абстрактного класса Car

Представим, что мы хотим создать базовый класс Car, который будет описывать, что должен уметь любой автомобиль.
Но мы не будем указывать, как именно это делать — каждый конкретный тип автомобиля реализует это по-своему.
Например, у всех автомобилей должен быть метод start_engine (запуск двигателя), но бензиновый и электрический автомобиль запускаются совершенно по-разному.

Пример:
    from abc import ABC, abstractmethod

    class Car(ABC):
        @abstractmethod
        def start_engine(self):
            """
            Абстрактный метод для запуска двигателя.
            Должен быть переопределён в подклассах.
            """
            pass

        def stop_engine(self):
            """
            Обычный метод (не абстрактный) — его можно переопределить, 
            но не обязательно. По умолчанию двигатель просто останавливается.
            """
            print("Двигатель остановлен.")

Слайд 7 — Как работает абстрактный класс

Класс Car наследуется от ABC, поэтому он является абстрактным — нельзя создать объект этого класса напрямую.
Метод start_engine помечен декоратором @abstractmethod, значит каждый класс-потомок обязан написать свою реализацию этого метода.
Метод stop_engine — это обычный метод с готовой реализацией, его можно использовать как есть или переопределить в потомках при необходимости.

Важно понимать:
- Нельзя создать объект абстрактного класса напрямую (car = Car() вызовет ошибку)
- Все абстрактные методы нужно обязательно реализовать в классах-потомках
- Обычные методы можно переопределить, но это не обязательно

Слайд 8 — Создание конкретных классов

Теперь создадим конкретные классы, которые наследуются от абстрактного класса Car.
Они обязаны реализовать метод start_engine, иначе Python выдаст ошибку и не позволит создать объект такого класса.

Пример:
    class GasolineCar(Car):
        def start_engine(self):
            print("Бензиновый двигатель запущен. Громкий рёв!")

    class ElectricCar(Car):
        def start_engine(self):
            print("Электродвигатель запущен. Тихий старт!")

Оба класса GasolineCar и ElectricCar должны переопределить метод start_engine.
Если бы мы этого не сделали, Python не дал бы создать объект такого класса (была бы ошибка TypeError).



Слайд 9 — Использование классов

Теперь мы можем создавать объекты конкретных классов (GasolineCar и ElectricCar) и вызывать их методы.
Благодаря абстрактному родительскому классу, мы гарантированно знаем, что у каждого объекта есть метод start_engine.

Пример:
    def demo():
        # Создаём объекты конкретных классов
        my_gas_car = GasolineCar()
        my_electric_car = ElectricCar()

        # Запускаем двигатели
        my_gas_car.start_engine()        # "Бензиновый двигатель запущен. Громкий рёв!"
        my_electric_car.start_engine()   # "Электродвигатель запущен. Тихий старт!"

        # Останавливаем двигатели (используем метод родительского класса)
        my_gas_car.stop_engine()         # "Двигатель остановлен."
        my_electric_car.stop_engine()    # "Двигатель остановлен."

Мы работаем с конкретными объектами, но при этом каждый из них точно имеет метод start_engine благодаря родительскому классу.
Если в будущем появится класс HybridCar (гибридный автомобиль), он тоже будет обязан реализовать метод start_engine по-своему.

Слайд 10 Инкапсуляция как пульт от телевизора

Инкапсуляция можно сравнить с пультом дистанционного управления от телевизора:
- Вы нажимаете кнопку включения — это интерфейс, способ взаимодействия
- Вам не нужно знать, как именно работает электроника внутри телевизора
- Телевизор просто включается, и это всё, что вам нужно

Главная идея Инкапсуляция: она скрывает всю сложность внутреннего устройства и показывает только то, что нужно для использования.
В тестах это значит, что вы можете использовать класс, не зная, как он работает внутри.

Слайд 11 — Инкапсуляция в действии

Инкапсуляция работает так: она прячет сложные детали и дает простой способ работы.

Пример 1: Встроенные функции — готовая Инкапсуляция
Когда мы вызываем метод .sort(), мы не думаем, как это работает — Python сам всё делает.
Нам не нужно знать алгоритм сортировки, достаточно просто вызвать метод.

Пример 2: Собственная Инкапсуляция
Инкапсуляция позволяет использовать систему, не зная, как она устроена.
Главное — это интерфейс, а детали спрятаны.

Пример:
    class Кофемашина:
        def сделать_кофе(self):
            self.нагреть_воду()
            self.помолоть_зерна()
            self.сварить_кофе()
            return "Готовый кофе"

        def нагреть_воду(self):
            print("Нагреваю воду...")

        def помолоть_зерна(self):
            print("Мелю зерна...")

        def сварить_кофе(self):
            print("Варю кофе...")

    машина = Кофемашина()
    print(машина.сделать_кофе())  # Готовый кофе

В тестах это помогает работать со сложными системами через простые методы.

Слайд 12 — Инкапсуляция в действии: пример с кофемашиной

Что происходит в этом примере:
1) Мы просто вызываем сделать_кофе(), не зная, как работает кофемашина внутри.
2) Внутри происходят сложные действия (нагрев воды, помол зерен, варка кофе), но нам это не важно.
3) Нам нужно только одно действие — получить кофе.

Пример:
    class Кофемашина:
        def сделать_кофе(self):
            self.нагреть_воду()
            self.помолоть_зерна()
            self.сварить_кофе()
            return "Готовый кофе"

        def нагреть_воду(self):
            print("Нагреваю воду...")

        def помолоть_зерна(self):
            print("Мелю зерна...")

        def сварить_кофе(self):
            print("Варю кофе...")

    машина = Кофемашина()
    print(машина.сделать_кофе())  # Готовый кофе

Итог: Абстракция позволяет работать со сложными системами через простой интерфейс, не вникая в детали реализации.
Это как водить машину, не будучи механиком!
В тестах это значит, что вы можете использовать сложные инструменты через простые методы.

Слайд 13 — Инкапсуляция

Инкапсуляция — это когда мы прячем данные объекта и не даем к ним доступ напрямую.
Это как пульт: вы управляете телевизором, не зная, как он устроен внутри.

В тестировании инкапсуляция помогает:

- скрыть сложность внутренней реализации

Слайд 14 — Приватные атрибуты в Python

В Python мы используем приватные атрибуты с подчеркиванием (_ или __) для скрытия данных.
И создаем методы для работы с этими данными.

Пример:
    class Car:
        def __init__(self, brand, model, fuel_level=0):
            self.brand = brand
            self.model = model
            self.__fuel_level = fuel_level  # Приватный атрибут, не доступный напрямую

        def refuel(self, amount):
            """Метод для заправки автомобиля"""
            if amount > 0:
                self.__fuel_level += amount
                if self.__fuel_level > 100:  # Предположим, что уровень топлива не может превышать 100%
                    self.__fuel_level = 100
                print(f"{self.brand} {self.model}: Добавлено {amount}% топлива. Текущий уровень: {self.__fuel_level}%.")
            else:
                print("Сумма для заправки должна быть положительной!")

Слайд 15 — Работа с приватными атрибутами

Продолжение примера с классом Car:
Метод drive() имитирует поездку и тратит топливо.
Метод get_fuel_level() возвращает текущий уровень топлива.

Пример:
    def drive(self, consumption):
        """Метод для симуляции поездки, во время которой расходуется топливо"""
        if consumption > self.__fuel_level:
            print(f"{self.brand} {self.model}: Недостаточно топлива для поездки!")
        else:
            self.__fuel_level -= consumption
            print(f"{self.brand} {self.model}: Поездка завершена. Осталось {self.__fuel_level}% топлива.")

    def get_fuel_level(self):
        """Метод для получения текущего уровня топлива"""
        return self.__fuel_level

# Пример использования:
    my_car = Car("Honda", "Civic", fuel_level=50)
    my_car.refuel(30)    # Закидываем 30% топлива
    my_car.drive(60)     # Расходуем 60% топлива на поездку
    print(f"Текущий уровень топлива: {my_car.get_fuel_level()}%")

Слайд 16 — Инкапсуляция как сейф

Инкапсуляцию можно сравнить с сейфом:
- Вы знаете, как положить или взять деньги (это интерфейс — методы deposit и withdraw)
- Но не видите, как работает замок (это скрыто)
- И не можете получить деньги напрямую, без методов (данные защищены)

В тестах это значит, что данные защищены от неправильного использования, и доступ контролируется через методы.

Слайд 17 — Простой пример инкапсуляции

Посмотрим пример класса BankAccount с инкапсуляцией:
Баланс скрыт от прямого доступа, работать с ним можно только через методы.

Пример:
    class BankAccount:
        def __init__(self, initial_balance=0):
            # __balance - приватное поле (скрыто от прямого доступа)
            self.__balance = initial_balance

        # Публичные методы - интерфейс для взаимодействия
        def deposit(self, amount):
            if amount > 0:
                self.__balance += amount
                print(f"Пополнение: +{amount} руб.")
            else:
                print("Сумма должна быть положительной")

        def withdraw(self, amount):
            if 0 < amount <= self.__balance:
                self.__balance -= amount
                print(f"Снятие: -{amount} руб.")
            else:
                print("Недостаточно средств или неверная сумма")

        def get_balance(self):
            return self.__balance

# Использование
    account = BankAccount(1000)
    account.deposit(500)    # Пополнение: +500 руб.
    account.withdraw(200)   # Снятие: -200 руб.
    print(f"Баланс: {account.get_balance()} руб.")  # Баланс: 1300 руб.

# Мы можем использовать только предоставленные методы
# Получить баланс можно только через метод
# А вот попытка прямого доступа к балансу не сработает:
# print(account.__balance)  # Ошибка! AttributeError

Слайд 18 — Что происходит в этом примере

В этом примере:
Сокрытие данных: Поле __balance скрыто и недоступно снаружи.
Нельзя просто написать account.__balance = 1000.

Контролируемый доступ: Баланс можно менять только через методы deposit и withdraw.
Это обеспечивает, что все операции проверяются.

Защита: Методы проверяют правильность операций (сумма должна быть больше нуля, нельзя взять больше, чем есть).

В тестах это помогает создавать надежные классы, которые защищены от неправильного использования.

Слайд 19 — Наследование

Наследование — это когда мы создаем новый класс на основе старого, добавляя или меняя его функции.

Пример:
Старые автомобили имели только: 4 колеса, двигатель, сидение, руль.
Это базовый класс.

Новые автомобили имеют еще: кондиционер, мультимедиа, автопилот.
Это классы-потомки, которые берут базовые функции и добавляют свои.

В тестах наследование помогает:
- использовать код повторно (не повторять одно и то же)
- добавлять возможности существующих классов
- создавать цепочки классов (например, BaseTest → LoginTest → AdminLoginTest)

Слайд 20 — Пример наследования: класс ElectricCar

Создадим класс ElectricCar, который наследуется от Car.
Электромобиль — это тоже автомобиль, поэтому у него есть все свойства автомобиля, плюс свои.

Пример:
    class ElectricCar(Car):
        def __init__(self, brand, model, battery_level, speed=0):
            super().__init__(brand, model, speed)
            self.battery_level = battery_level  # Уровень заряда батареи

        def charge(self, amount):
            self.battery_level = min(100, self.battery_level + amount)
            print(f"Батарея заряжена до {self.battery_level}%")

        def display_info(self):
            # Переопределение метода для вывода дополнительной информации
            print(f"Электромобиль: {self.brand} {self.model}, Скорость: {self.speed} км/ч, Заряд: {self.battery_level}%")

# Создание объекта класса ElectricCar:
    e_car = ElectricCar("Tesla", "Model 3", battery_level=50)
    e_car.accelerate(40)
    e_car.charge(30)
    e_car.display_info()

Слайд 21 — Наследование как семейная черта

Наследование работает как семейные черты:
- Дочерний класс получает всё от родительского (все свойства и методы)
- Может добавить свои методы и свойства
- Может переписать методы родителя по-своему

В тестах дочерний класс наследует всё от базового класса и может расширить или изменить функциональность.

Слайд 22 — Суть наследования

Наследование позволяет создавать новые классы на основе существующих, переиспользуя их код и добавляя свой.

Простая аналогия:
Все автомобили имеют общие части (колеса, двигатель).
Но электромобиль и бензиновый автомобиль по-разному заправляются — один заряжается, другой заправляется топливом.

В тестах можно создать базовый класс BaseTest с общими методами, а затем создать специализированные классы LoginTest, RegistrationTest,
которые наследуют общую функциональность и добавляют свою специфику.


Слайд 23 — Полиморфизм

Полиморфизм — это способность разных объектов выполнять одинаковые действия по-разному.

Простыми словами: разные классы могут иметь методы с одинаковыми именами, но с разной реализацией.
При вызове метода Python автоматически выбирает правильную реализацию в зависимости от типа объекта.

Пример:
    # Рассмотрим пример с методом start_engine
    class Car:
        def __init__(self, brand, model):
            self.brand = brand
            self.model = model

    class GasolineCar(Car):
        def start_engine(self):
            print(f"{self.brand} {self.model}: Двигатель бензинового автомобиля запущен.")

    class ElectricCar(Car):
        def start_engine(self):
            print(f"{self.brand} {self.model}: Электродвигатель запущен, тихий старт!")

    # Создание объектов разных классов:
    cars = [GasolineCar("Ford", "Focus"), ElectricCar("Nissan", "Leaf")]

    # Вне зависимости от типа автомобиля, вызываем метод start_engine:
    for car in cars:
        car.start_engine()

В тестах полиморфизм позволяет писать универсальный код, который работает с разными типами объектов без необходимости знать их конкретный тип заранее.

Слайд 24 — Простой пример кода

Рассмотрим пример полиморфизма на животных:
У разных классов есть метод с одинаковым именем, но каждый класс реализует его по-своему.

Пример:
    # Разные классы с одинаковым методом
    class Собака:
        def звук(self):
            return "Гав-гав!"

    class Кошка:
        def звук(self):
            return "Мяу!"

    class Корова:
        def звук(self):
            return "Мууу!"

    # Функция, которая работает с любым объектом, у которого есть метод звук()
    def издать_звук(животное):
        print(животное.звук())

    # Использование
    собака = Собака()
    кошка = Кошка()
    корова = Корова()
    издать_звук(собака)  # Гав-гав!
    издать_звук(кошка)   # Мяу!
    издать_звук(корова)  # Мууу!

В примере все классы имеют метод звук(), но реализация у каждого своя.
Функция издать_звук() может работать с любым объектом, у которого есть метод звук(), не зная заранее его тип.

Слайд 25 — Что здесь происходит

В примере с животными происходит следующее:
- Разные классы (Собака, Кошка, Корова) имеют метод с одинаковым именем
- Функция издать_звук() может работать с любым объектом, у которого есть этот метод
- Каждый объект выполняет метод по-своему, в зависимости от своего класса

В тестах это позволяет создавать универсальные функции, которые работают с разными объектами, если у них есть нужный метод.

Слайд 26 — Декораторы в Python

Декораторы представляют собой функции, изменяющие работу других функций.
Они расширяют возможности функций, не затрагивая их исходный код.

@my_decorator_name
def my_function():
    pas

Если объяснить просто: декоратор — это оболочка для функции.
Он оборачивает функцию и наделяет её дополнительными возможностями (логирование, валидация, измерение времени и прочее).

В тестировании декораторы используются для:
- записи логов при выполнении тестов
- отслеживания длительности выполнения
- автоматических повторов при сбоях
- условного исключения тестов из прогона

Слайд 27 — Простые и параметризованные декораторы

Простой декоратор заключает функцию в обертку и запускает дополнительный код перед и после её выполнения.

Пример простого декоратора:
    def decorator(func):
        def wrapper():
            print("Начало выполнения функции")
            func()
            print("Конец выполнения функции")
        return wrapper

    @decorator
    def greet():
        print("Привет!")

    greet()

    # Результат:
    # Начало выполнения функции
    # Привет!
    # Конец выполнения функции

Параметризованный декоратор дает возможность настраивать его работу с помощью параметров.

Пример декоратора с параметрами:
    def repeat(num_times):
        def decorator_repeat(func):
            def wrapper(*args, **kwargs):
                for _ in range(num_times):
                    func(*args, **kwargs)
            return wrapper
        return decorator_repeat

    @repeat(num_times=3)
    def say_hello(name):
        print(f"Привет, {name}!")

    say_hello("Анна")

    # Результат:
    # Привет, Анна!
    # Привет, Анна!
    # Привет, Анна!

В тестировании параметризованные декораторы помогают, когда требуется настроить поведение (число повторов, таймауты и прочие настройки).

Слайд 28 — Декоратор — это как обертка для подарка

Декоратор действует подобно обертке для подарка:
- Функция — это сам подарок
- Декоратор — это обертка, дополняющая подарок, но не меняющая его содержимое
- Одну и ту же обертку можно применять к разным подаркам

Пример:
    # Декоратор - "обёртка" для функции
    def мой_декоратор(функция):
        def обертка():
            print("Начинаем работу...")  # Действие ДО основной функции
            функция()  # Вызываем саму функцию
            print("Завершаем работу.")  # Действие ПОСЛЕ основной функции
        return обертка

    # Создаем обычную функцию
    def сказать_привет():
        print("Привет, мир!")

    # Применяем декоратор к функции
    сказать_привет = мой_декоратор(сказать_привет)

    # Вызываем саму функцию
    сказать_привет()

    # Вывод:
    # Начинаем работу...
    # Привет, мир!
    # Завершаем работу.

В тестировании можно написать один декоратор для логирования и использовать его в разных тестах, не меняя их код.

Слайд 29 — Реальный пример: замер времени выполнения функции

Практический пример: декоратор способен отслеживать длительность выполнения функции и показывать результат.

Пример:
    import time

    def замер_времени(функция):
        def обёртка():
            начало = time.time()
            функция()
            конец = time.time()
            print(f"Функция выполнялась {конец - начало:.2f} секунд")
        return обёртка

    @замер_времени
    def долгая_операция():
        print("Выполняю сложные вычисления...")
        time.sleep(2)
        # Имитация долгой операции

    долгая_операция()

    # Вывод:
    # Выполняю сложные вычисления...
    # Функция выполнялась 2.00 секунд

В тестировании это позволяет выявить медленные тесты, которые нуждаются в оптимизации.

Слайд 30 — Как это работает — простыми словами

Принцип работы декоратора:
Декоратор — это функция, получающая другую функцию как аргумент.
Внутренняя функция-обертка:
- Запускает код до выполнения основной функции
- Вызывает саму функцию
- Запускает код после выполнения основной функции

В тестировании это дает возможность внедрять дополнительную логику до и после теста, не трогая код самого теста.

Пример:
    class Person:
        species = "Homo sapiens"  # Атрибут класса

        def __init__(self, name, age):
            self.name = name
            self.age = age

        @classmethod
        def from_birth_year(cls, name, birth_year):
            """Альтернативный конструктор"""
            age = 2024 - birth_year
            return cls(name, age)

        @classmethod
        def get_species(cls):
            return cls.species

    person1 = Person("Иван", 25)
    person2 = Person.from_birth_year("Мария", 1995)
    print(Person.get_species())  # Homo sapiens

В тестировании методы класса помогают создавать объекты различными способами или работать с общими настройками.

Слайд 31 — Декораторы методов внутри класса

Метод с декоратором @classmethod принимает класс как первый аргумент (обычно именуется cls), а не экземпляр (self).

Это открывает возможности:
- Реализовывать альтернативные варианты создания объектов
- Оперировать общими атрибутами класса, общими для всех экземпляров
- Менять состояние класса целиком

В тестировании методы класса подходят для создания объектов различными способами или для работы с общими настройками тестового класса.

Слайд 32 — Метод класса (@classmethod)

Пример использования @classmethod:

Пример:
    class Car:
        car_count = 0  # Атрибут класса – общее количество машин

        def __init__(self, brand, model):
            self.brand = brand
            self.model = model
            Car.car_count += 1

        @classmethod
        def from_string(cls, car_str):
            # Альтернативный конструктор, создающий объект из строки "Brand-Model"
            brand, model = car_str.split('-')
            return cls(brand, model)

    # Пример использования
    car1 = Car.from_string("Toyota-Corolla")
    print(f"Бренд: {car1.brand}, Модель: {car1.model}")
    print(f"Всего автомобилей: {Car.car_count}")

Основная суть: @classmethod применяется для альтернативных вариантов создания объектов и работы с атрибутами класса.

Слайд 33 — Как это работает — простыми словами

@classmethod — это декоратор, дающий возможность создавать методы, оперирующие классом, а не отдельным экземпляром.
Такие методы принимают класс (cls) как первый параметр вместо экземпляра (self).

Пример:
    class Employee:
        company = "TechCorp"  # Обычная переменная класса (общая для всех объектов)

        def __init__(self, name, salary):
            self.name = name
            self.salary = salary

        def display_info(self):
            # Обычный метод - работает с конкретным объектом (self)
            print(f"{self.name} зарабатывает {self.salary} в компании {self.company}")

        @classmethod
        def change_company(cls, new_company):
            # Метод класса - работает с классом в целом (cls)
            cls.company = new_company
            print(f"Название компании изменено на: {new_company}")

        @classmethod
        def from_string(cls, employee_string):
            # Ещё один полезный пример - альтернативный конструктор
            name, salary = employee_string.split("-")
            return cls(name, int(salary))

    # Создаем объекты
    emp1 = Employee("Иван", 50000)
    emp2 = Employee("Мария", 60000)

    # Используем обычный метод
    emp1.display_info()  # Иван зарабатывает 50000 в компании TechCorp

    # Используем метод класса - меняем компанию для ВСЕХ объектов
    Employee.change_company("NewTech")

    # Теперь все объекты используют новое название компании
    emp1.display_info()  # Иван зарабатывает 50000 в компании NewTech
    emp2.display_info()  # Мария зарабатывает 60000 в компании NewTech

    # Используем альтернативный конструктор
    emp3 = Employee.from_string("Петр-70000")
    emp3.display_info()  # Петр зарабатывает 70000 в компании NewTech

В тестировании это пригодится, когда требуется создать объект из строки, JSON или иных форматов данных.

Слайд 34 — Декораторы методов внутри класса

Метод с декоратором @staticmethod не принимает ни self, ни cls в качестве аргументов.
Он функционирует как обычная функция, но по смыслу относится к классу.

Это подходит, когда функция связана с классом, но не зависит ни от конкретного экземпляра, ни от самого класса.

Пример:
    class Vehicle:
        @staticmethod
        def is_motorcycle(wheels):
            return wheels == 2

    print(Vehicle.is_motorcycle(2))  # True
    print(Vehicle.is_motorcycle(4))  # False

Основная суть: Метод is_motorcycle не зависит ни от класса, ни от экземпляра.
Он просто выполняет проверку на основе переданных данных, поэтому корректно объявлен как @staticmethod.

В тестировании статические методы подходят для вспомогательных функций, которые логически относятся к классу, но не нуждаются в доступе к его данным.

Слайд 35 — Декораторы методов внутри класса

Статические методы используются для функций, которые логически связаны с классом, но не нуждаются в доступе к его данным или состоянию.

Пример:
    class Car:
        def __init__(self, brand, model):
            self.brand = brand
            self.model = model

        @staticmethod
        def is_motorcycle(wheels):
            """Метод проверяет, является ли транспортное средство мотоциклом,
            исходя из количества колес."""
            return wheels == 2

    # Пример использования
    print(f"2 колеса - это мотоцикл? {Car.is_motorcycle(2)}")  # True
    print(f"4 колеса - это мотоцикл? {Car.is_motorcycle(4)}")  # False

В тестировании это удобно для вспомогательных функций, которые помогают работать с данными класса, но не зависят от конкретного экземпляра.

Слайд 36 — Свойства класса (@property)

Декоратор @property преобразует метод в свойство объекта, доступное как обычный атрибут, но с выполнением кода внутри
(валидация, вычисления и прочее).

Представьте автомобиль со спидометром:
- внутри хранится значение скорости
- вы не меняете его напрямую
- система автоматически проверяет корректность данных
- при необходимости данные пересчитываются или сбрасываются

В этом суть @property — контролируемый доступ к данным.

Основная идея:
- Дает возможность добавить валидацию, логику, ограничения
- Упрощает использование (обращение без скобок, как к переменной)

В тестировании @property помогает создавать "умные" свойства, проверяющие данные при установке или вычисляющие значения при чтении.

Слайд 37 — Пример использования @property в классе Car

Создаем класс Car, где скорость хранится в приватном атрибуте __speed. Для безопасного управления добавляем геттер и сеттер с валидацией.

Пример:
    class Car:
        def __init__(self, brand, model, speed_car=0):
            self.brand = brand
            self.model = model
            self.speed = speed_car  # Приватный атрибут скорости

        @property
        def speed(self):
            """Геттер для получения скорости автомобиля."""
            return self.__speed

        @speed.setter
        def speed(self, value):
            """Сеттер с проверкой диапазона значений."""
            if value < 0:
                print("Ошибка: скорость не может быть отрицательной!")
            elif value > 300:
                print("Ошибка: превышено максимально допустимое значение скорости (300 км/ч)!")
            else:
                self.__speed = value

@property защищает внутренние данные (__speed) и дает возможность обращаться к ним как к обычным атрибутам, но с дополнительной логикой валидации.

Слайд 38 — Пример работы с @property, setter и deleter

@property делает метод доступным как свойство (car.speed).
@speed.setter дает возможность добавлять валидацию данных при установке значения.
@speed.deleter задает поведение при удалении свойства.

Пример:
    car = Car("Toyota", "Corolla")

    # Чтение значения скорости (вызов getter)
    print(f"Начальная скорость: {car.speed} км/ч")

    # Установка нового значения скорости (вызов setter)
    car.speed = 150
    print(f"Обновленная скорость: {car.speed} км/ч")

    # Попытка установить некорректное значение (отрицательное)
    car.speed = -20

    # Попытка установить слишком высокую скорость
    car.speed = 350

    # Удаление свойства скорости (вызов deleter)
    del car.speed

Это делает работу с данными понятнее и безопаснее. Итог: property сочетает инкапсуляцию и удобство использования.
Обращаетесь к методу как к свойству — без скобок, но с кодом внутри.

В тестировании это дает возможность создавать удобные способы работы с данными, сохраняя контроль над их валидацией.

Слайд 39 — Context Manager (Менеджеры контекста)

Менеджеры контекста управляют ресурсами (файлами, сетевыми соединениями, базами данных) и обеспечивают их корректное закрытие, даже если в коде возникла ошибка.

Контекстный менеджер автоматически выполняет последовательность "открыть → использовать → закрыть",
освобождая программиста от ручного контроля этого процесса.

Основные преимущества:
- Безопасное использование ресурсов
- Автоматическое закрытие даже при ошибках
- Чистый и лаконичный код

Пример: Представьте автомобиль — завести двигатель (использовать ресурс), заглушить двигатель (освободить ресурс).
Если водитель забудет заглушить двигатель, система сделает это автоматически.

В тестировании контекстные менеджеры применяются для работы с файлами, базами данных, сетевыми соединениями и прочими ресурсами,
которые нужно закрывать после использования.

Слайд 40 — Зачем нужен контекстный менеджер

Контекстный менеджер обеспечивает, что после использования ресурса (файл, сеть, база данных и прочее) он будет корректно закрыт —
даже если в коде произошла ошибка.

Пример:
    with open("example.txt", "w") as file:
        file.write("Записываем данные")
   # После выхода из блока with файл будет автоматически закрыт
В тестировании это важно, так как обеспечивает закрытие ресурсов даже если тест завершится с ошибкой.

Слайд 41 — Самый простой пример — работа с файлами

Наиболее распространенный пример контекстного менеджера — работа с файлами:

Пример:
    # Обычный способ работы с файлом (без менеджера контекста)
    file = open("example.txt", "w")
    try:
        file.write("Привет, мир!")
    finally:
        file.close()  # Всегда нужно не забыть закрыть файл

    # То же самое с менеджером контекста (автоматическое закрытие)
    with open("example.txt", "w") as file:
        file.write("Привет, мир!")
    # Файл автоматически закроется после выхода из блока with

В тестировании это используется для создания временных файлов, чтения настроек и работы с логами.

Слайд 42 — Пример: Контекстный менеджер для сервисного обслуживания автомобиля

Представим, что автомобиль поступает в сервис. Создадим класс CarService, который будет функционировать как контекстный
 менеджер.

При входе автомобиль принимается в сервис, а при выходе автоматически освобождается (завершается обслуживание, закрываются соединения
с оборудованием и прочее).

В тестировании это можно применять для имитации работы с внешними сервисами или для управления тестовым окружением.

Слайд 43 — Пример: Контекстный менеджер для сервисного обслуживания автомобиля
Пример контекстного менеджера:

Пример:
    class Car:
        def __init__(self, brand, model):
            self.brand = brand
            self.model = model

        def service_check(self):
            # Метод имитирует проверку автомобиля в сервисе
            print(f"Проводится диагностика автомобиля {self.brand} {self.model}.")

        def __str__(self):
            return f"{self.brand} {self.model}"

    class CarService:
        def __init__(self, car):
            self.car = car

        def __enter__(self):
            # Код, выполняющийся при входе в контекст
            print(f"Автомобиль {self.car} поступил в сервисное обслуживание.")
            # Например, можно открыть соединение с оборудованием диагностики
            return self.car  # возвращаем автомобиль для работы внутри блока with

        def __exit__(self, exc_type, exc_value, traceback):
            # Код, выполняющийся при выходе из контекста
            if exc_type:
                print(f"Во время обслуживания автомобиля {self.car} произошла ошибка: {exc_value}")
            print(f"Автомобиль {self.car} покидает сервисное обслуживание.")
            # Здесь можно закрыть соединения, освободить ресурсы и т.д.
            # Возвращаем False, чтобы исключения, если они есть, не подавлялись.
            return False

# Пример использования контекстного менеджера:
    my_car = Car("BMW", "X5")
    with CarService(my_car) as car_in_service:
        car_in_service.service_check()
        # Если требуется, можно сымитировать ошибку:
        # raise ValueError("Проблема с оборудованием диагностики")

Слайд 44 — Объяснение примера



# С with
with CarService(car) as service:
    print("Работаем...")
    # raise ValueError("Ошибка!")

# Это эквивалентно:
service = CarService(car)
try:
    service.__enter__()
    print("Работаем...")
    # raise ValueError("Ошибка!")
finally:
    service.__exit__(None, None, None)  # ВСЕГДА вызывается



Метод __enter__: При входе в блок with вызывается метод __enter__, который подготавливает ресурс (например, принимает автомобиль в сервис).
Возвращаемое значение (сам автомобиль) присваивается переменной после ключевого слова as.

Метод __exit__: После завершения блока with (или при возникновении ошибки) вызывается метод __exit__.
Он выполняет финальные действия: освобождение ресурсов, закрытие соединений, запись ошибок и прочее.
Если произошла ошибка, информация о ней передается через параметры exc_type, exc_value и traceback.

Преимущества: Используя контекстный менеджер, не требуется писать try...finally для выполнения финальных действий.
Код становится проще и понятнее.

В тестировании это обеспечивает, что ресурсы будут закрыты даже при возникновении ошибок.

Слайд 45 — Dataclass — упрощённое создание классов для хранения данных

Вместо ручного написания __init__, __repr__ и __eq__ достаточно указать @dataclass — Python автоматически создаст эти методы.

Что @dataclass генерирует автоматически:
- __init__() — создает конструктор и инициализирует атрибуты
- __repr__() — возвращает понятное текстовое представление объекта
- __eq__() — сравнивает объекты по их данным
- другие полезные методы

Это сокращает объем повторяющегося кода и делает класс более лаконичным и понятным.

@dataclass — это декоратор, добавленный в Python 3.7, который автоматически создаёт базовую структуру класса без шаблонного кода.

В тестировании dataclass помогает создавать классы данных (например, для тестовых данных, настроек и прочего).

Слайд 46 — Пример: класс автомобиля с использованием @dataclass

Рассмотрим, как создать класс для автомобиля, применяя @dataclass.
В классе будут основные атрибуты автомобиля — марка, модель, год и скорость (по умолчанию 0). Также добавим методы для изменения скорости.

Пример:
    from dataclasses import dataclass

    @dataclass
    class Car:
        brand: str
        model: str
        year: int
        speed: int = 0

        def accelerate(self, increment: int):
            """Увеличивает скорость автомобиля."""
            self.speed += increment
            print(f"{self.brand} {self.model} ускоряется до {self.speed} км/ч.")

        def brake(self, decrement: int):
            """Уменьшает скорость автомобиля, не опускаясь ниже 0."""
            self.speed = max(0, self.speed - decrement)
            print(f"{self.brand} {self.model} замедляется до {self.speed} км/ч.")

    # Использование:
    car = Car("Audi", "A4", 2022)
    print(car)  # Автоматически использует __repr__
    car.accelerate(50)  # Audi A4 ускоряется до 50 км/ч.
    car.brake(20)  # Audi A4 замедляется до 30 км/ч.

В тестировании это помогает быстро создавать классы для хранения данных без необходимости писать много повторяющегося кода.

Слайд 47 — Что происходит в примере

Что здесь написано вручную:
__init__ — конструктор для создания объекта
__repr__ — строковое представление для print()
__eq__ — сравнение объектов через ==

Декоратор @dataclass автоматически создает конструктор __init__(), поэтому не требуется вручную писать инициализацию атрибутов.
Автоматически созданный метод __repr__() помогает выводить информацию об объекте.
Методы accelerate и brake добавляют функциональность для изменения скорости.

В тестировании это означает, что можно быстро создать класс для тестовых данных и сразу использовать его.

Слайд 48 — Простой пример: класс без и с @dataclass

До — обычный класс требует ручного написания __init__, __repr__, __eq__.

Пример:
    class Person:
        def __init__(self, name, age):
            self.name = name
            self.age = age

        def __repr__(self):
            return f"Person(name={self.name}, age={self.age})"

        def __eq__(self, other):
            if not isinstance(other, Person):
                return False
            return self.name == other.name and self.age == other.age

После — тот же класс с @dataclass автоматически получает все эти методы.

Пример:
    from dataclasses import dataclass

    @dataclass
    class PersonData:
        name: str
        age: int

    # Использование:
    person1 = PersonData("Иван", 25)
    person2 = PersonData("Мария", 30)
    print(person1)  # PersonData(name='Иван', age=25)
    print(person2)  # PersonData(name='Мария', age=30)
    print(person1 == person2)  # False

В тестировании это экономит время и сокращает объем кода, необходимого для написания и поддержки.

Слайд 49 — Итоги

Что dataclass генерирует автоматически:
- __init__ — конструктор для инициализации атрибутов
- __repr__ — понятное текстовое представление объекта
- __eq__ — сравнение объектов по их данным
- __hash__ (опционально) — для использования в словарях и множествах

Преимущества dataclass:
- Меньше кода — не требуется писать повторяющиеся методы вручную
- Понятность — атрибуты класса видны сразу в объявлении класса
- Безопасность — возможность проверки типов (если указать типы)
- Гибкость — можно добавлять свои методы и логику

В тестировании dataclass особенно полезен для создания тестовых данных, настроек и других структур данных.

Слайд 50 — Итераторы и генераторы в Python

Итераторы — это объекты, дающие возможность перебирать элементы коллекции по одному.

Генераторы — это функции, создающие значения по требованию, экономя память.

Применяются везде, где важна пошаговая обработка данных: списки, файлы, потоки, API, создание объектов и прочее.

В тестировании итераторы и генераторы помогают для:
- обработки больших объемов данных
- создания тестовых данных по требованию
- работы с API, которые возвращают данные частями

Слайд 51 — Что делает итератор

Итератор — это объект, реализующий два метода:
- __iter__() — возвращает сам итератор
- __next__() — возвращает следующий элемент или вызывает StopIteration, когда элементы закончились

В тестировании итераторы дают возможность перебирать коллекции (например, список пользователей) по одному элементу.

Слайд 52 — Пример: Автосалон с автомобилями

Пример итератора для перебора автомобилей в автосалоне:

Пример:
    class Car:
        def __init__(self, brand, model, year):
            self.brand = brand
            self.model = model
            self.year = year

        def __str__(self):
            return f"{self.brand} {self.model} ({self.year})"

    class CarLot:
        def __init__(self, cars):
            self.cars = cars
            self.index = 0

        def __iter__(self):
            return self

        def __next__(self):
            if self.index < len(self.cars):
                car = self.cars[self.index]
                self.index += 1
                return car
            else:
                raise StopIteration

    # Использование итератора:
    lot = CarLot([
        Car("Toyota", "Corolla", 2020),
        Car("Honda", "Civic", 2019),
        Car("Ford", "Mustang", 2021)
    ])

    for car in lot:
        print(car)

Что происходит: Цикл for автоматически вызывает __next__(), пока автомобили не закончатся — итерируем коллекцию как в реальном автосалоне.

В тестировании это дает возможность перебирать тестовые данные по одному, не загружая все данные в память сразу.

Слайд 53 — Генераторы

Генератор — это функция, сохраняющая своё состояние между вызовами и возвращающая по одному элементу через ключевое слово yield.

Пример: генератор для автопроизводства

Пример:
    def car_factory(total):
        """Генератор, имитирующий производство автомобилей."""
        for i in range(1, total + 1):
            yield Car("BrandX", f"Model-{i}", 2020 + i)

    for car in car_factory(5):
        print(car)

Что происходит: Каждый yield возвращает новый автомобиль — автомобили создаются по требованию, а не все сразу.

В тестировании генераторы помогают создавать тестовые данные по требованию, не создавая все данные заранее.

Слайд 54 — Как работает генератор

При вызове функции-генератора она не выполняется сразу, а возвращает объект-генератор. При вызове next() выполняется код до первого yield.
Функция сохраняет состояние и продолжает выполнение с места остановки при следующем вызове.

Пример из жизни:
- Обычная функция → вся пицца сразу 🍕
- Генератор → по кусочку когда нужно 🍕🍕🍕

Суть генераторов: это функции, способные создавать последовательности значений по одному, экономя память и давая возможность работать
с бесконечными или очень большими последовательностями данных.

В тестировании генераторы особенно полезны для создания больших объемов тестовых данных не загружая все сразу.
