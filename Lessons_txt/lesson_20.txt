Слайд 2 — Импортирование в Python

Импортирование — это способ подключения кода из других модулей в ваш текущий файл. Это основа для повторного
использования кода и организации больших проектов.

С помощью импортирования можно использовать:
- встроенные библиотеки Python (например, os, json, datetime)
- сторонние библиотеки, установленные через pip (например, requests, pytest)
- собственные модули, которые вы создали в своем проекте

Импортирование позволяет разделить код на логические части: один файл для работы с данными, другой для тестов, третий
для утилит. Это делает код более понятным и легким в поддержке.

В тестировании импортирование особенно полезно: можно создать отдельные модули для тестовых данных, вспомогательных
функций и самих тестов.

Слайд 3 — Основы импортирования

В Python есть несколько способов импортировать код из других модулей.

Первый способ — импорт всего модуля целиком:
    import requests
    import json

После этого можно использовать функции и классы через точку: requests.get(), json.dumps().

Второй способ — импорт конкретных функций или классов:
    from requests import get, post
    from json import dumps, loads

Теперь можно использовать функции напрямую без указания модуля: get(), post().

Рекомендация: используйте точечный импорт (from ... import ...), когда нужны только отдельные функции. Это делает код
короче и понятнее, а также помогает избежать конфликтов имен.

Слайд 4 — Пример с директорией

Рассмотрим практический пример организации проекта с импортированием.

Представим структуру проекта:
    project/
        randomayzer.py    # Модуль с функциями для рандомизации
        tests.py          # Файл с тестами

В файле randomayzer.py хранятся вспомогательные функции, например, для генерации случайных данных.

В файле tests.py мы можем импортировать эти функции:
    from randomayzer import generate_random_email, generate_random_name

Вывод: можно вынести все вспомогательные функции (генерация данных, форматирование, валидация) в отдельные модули и
импортировать их по необходимости. Это делает проект чище, удобнее и позволяет легко масштабировать код.

Слайд 5 — Что такое API автотесты

API автотесты — это автоматизированные проверки, которые тестируют работу программных интерфейсов без использования
графического интерфейса.

Представьте ситуацию: вы заказываете еду через мобильное приложение. Когда вы нажимаете "Заказать", приложение
отправляет запрос на сервер через API. API-тесты проверяют, что этот запрос обрабатывается правильно, даже без
открытия самого приложения.

Главная идея: API-тесты проверяют логику работы системы и взаимодействие между компонентами, а не внешний вид
интерфейса. Они работают напрямую с сервером, отправляя запросы и проверяя ответы.

В тестировании это означает, что мы можем проверить работу системы еще до того, как будет готов пользовательский интерфейс.

Слайд 6 — Зачем нужны API-тесты

API-тесты имеют несколько важных преимуществ перед UI-тестами:

Быстрота — API-тесты выполняются значительно быстрее, чем тесты через графический интерфейс. Нет необходимости
ждать загрузки страниц, отрисовки элементов и действий пользователя.

Надежность — тесты не зависят от изменений в интерфейсе. Если дизайнер изменил кнопку или переместил элемент,
API-тесты продолжат работать, так как они проверяют логику, а не внешний вид.

Раннее тестирование — можно начинать тестировать API сразу после его разработки, не дожидаясь готовности фронтенда.
Это позволяет находить ошибки на ранних этапах.

Глубокое тестирование — API-тесты позволяют проверить бизнес-логику и поведение системы на уровне кода.
Можно проверить обработку ошибок, валидацию данных, работу с базой данных и другие внутренние процессы.

Слайд 7 — Основные понятия API: HTTP-методы

API можно сравнить с рестораном: вы делаете заказ (отправляете запрос), официант передает его на кухню (сервер),
а затем приносит блюдо (ответ). Коды статусов — это язык общения между вами и кухней.

HTTP-методы — это способы взаимодействия с сервером:

GET — получение данных. Используется для чтения информации, например, получить список пользователей или данные о товаре.

POST — создание новых данных. Используется для отправки информации на сервер, например,
создать нового пользователя или отправить сообщение.

PUT — полное обновление данных. Заменяет существующий ресурс новыми данными.

PATCH — частичное обновление данных. Изменяет только указанные поля ресурса.

DELETE — удаление данных. Удаляет указанный ресурс с сервера.

В тестировании мы используем эти методы для проверки различных операций с данными.

Слайд 8 — Основные понятия API: Коды ответа

Коды ответа (статус-коды) — это способ сервера сообщить клиенту о результате выполнения запроса.
Это как ответ официанта: "Ваш заказ принят" или "Такого блюда нет в меню".

Основные группы кодов:

2xx — успешные ответы:
    200 OK — запрос выполнен успешно
    201 Created — новый ресурс создан
    204 No Content — запрос выполнен, но ответ пустой

4xx — ошибки клиента:
    400 Bad Request — неправильный запрос (неверные данные)
    401 Unauthorized — требуется авторизация
    403 Forbidden — доступ запрещен
    404 Not Found — ресурс не найден

5xx — ошибки сервера:
    500 Internal Server Error — внутренняя ошибка сервера
    502 Bad Gateway — проблема с прокси-сервером
    503 Service Unavailable — сервис временно недоступен

В тестах мы проверяем статус-коды, чтобы убедиться, что запрос обработан правильно.

Слайд 9 — Пример простого API-теста

Рассмотрим пример теста для API получения данных о погоде.

Что делает такой тест:
1. Отправляет GET-запрос к API погоды
2. Проверяет, что запрос выполнен успешно (статус-код 200)
3. Валидирует структуру JSON-ответа (проверяет наличие нужных полей)
4. Проверяет корректность данных (например, температура в разумных пределах)

Результат: если все проверки пройдены, значит API работает корректно, структура ответа соответствует документации,
и данные имеют правильный формат.

Такой тест можно запускать автоматически при каждом изменении кода, чтобы убедиться, что API продолжает работать правильно.

Слайд 10 — Как писать API тесты: простые шаги

Процесс написания API-теста можно разбить на несколько простых шагов:

1. Определите конечные точки (URL адреса), которые нужно тестировать. Это адреса API, к которым будут отправляться
запросы, например: https://api.example.com/users

2. Подготовьте тестовые данные — что будете отправлять в запросах. Это может быть информация для создания пользователя,
параметры поиска или данные для обновления.

3. Отправьте запрос, используя соответствующий HTTP-метод (GET, POST, PUT, DELETE). Выберите правильный метод в
зависимости от того, что вы хотите сделать.

4. Проверьте ответ — статус-код, структуру данных, значения полей. Убедитесь, что сервер вернул ожидаемый результат.

5. Очистите за собой — удалите тестовые данные, если они были созданы. Это важно,
чтобы не засорять базу данных тестовыми записями.

Следуя этим шагам, можно создать надежные и понятные API-тесты.

Слайд 12 — Requests — библиотека для работы с API

Библиотека requests — это стандартный инструмент для выполнения HTTP-запросов в Python.

С ее помощью можно:
- отправлять различные типы запросов к API (GET, POST, PUT, DELETE)
- получать и обрабатывать ответы от серверов
- работать с заголовками, параметрами и телом запросов
- взаимодействовать с веб-сервисами напрямую

Установка библиотеки выполняется командой:
    pip install requests

Зачем нужна: requests делает работу с API простой и читаемой. Она заменяет громоздкие
стандартные модули Python (например, urllib) более удобным и понятным интерфейсом.
Код с requests получается короче и легче для понимания.

В тестировании requests — это основной инструмент для отправки запросов к API и проверки ответов.

Слайд 13 — Основы отправки HTTP-запросов: GET-запрос

GET-запрос используется для получения данных с сервера. В Python это делается с помощью метода requests.get().

Пример:
    response = requests.get("https://api.example.com/users")

Что происходит:
1. requests.get() отправляет GET-запрос к указанному адресу
2. Сервер обрабатывает запрос и возвращает ответ с данными
3. Результат сохраняется в переменную response, которая содержит всю информацию об ответе

Используется для: получения данных из API, чтения статей, просмотра списка объектов и другой информации с веб-сервера.
GET-запросы не изменяют данные на сервере, они только читают информацию.

В тестах GET-запросы используются для проверки, что API правильно возвращает данные.

Слайд 14 — Основы отправки HTTP-запросов: POST-запрос

Метод POST используется для отправки данных на сервер, например, при создании новой записи или отправке формы.

Пример:
    data = {"name": "Иван", "email": "ivan@test.com"}
    response = requests.post("https://api.example.com/users", json=data)

Как это работает:
1. requests.post() отправляет данные на сервер
2. Аргумент json={} автоматически преобразует словарь Python в формат JSON
3. Переменная response хранит ответ от сервера: код состояния, тело ответа и другую информацию

Используется для: создания записей, отправки форм, регистрации пользователей, аутентификации и любой передачи
данных через API. POST-запросы изменяют состояние на сервере, создавая или обновляя данные.

В тестах POST-запросы используются для проверки создания новых ресурсов и обработки отправленных данных.

Слайд 15 — Обработка ответов от API: Статус-коды

Каждый ответ от сервера содержит статус-код, который сообщает результат выполнения запроса.

Пример проверки статус-кода:
    response = requests.get("https://api.example.com/users")
    print(response.status_code)  # 200

Статус-код помогает определить, успешно ли сработал запрос и нужно ли обрабатывать ошибку.

Что означают основные коды:
- 200 — запрос успешно выполнен, данные получены
- 201 — новый объект успешно создан
- 400 — ошибка в запросе (неверные данные или формат)
- 404 — запрашиваемый ресурс не найден
- 500 — внутренняя ошибка на сервере

В тестах мы проверяем статус-коды, чтобы убедиться, что API работает правильно. Например, после создания пользователя
ожидаем код 201, а при попытке получить несуществующий ресурс — код 404.

Слайд 16 — Заголовки (Headers) в запросах и ответах

Заголовки (headers) передают дополнительную информацию между клиентом и сервером: формат данных, авторизацию,
язык, тип контента и другие метаданные.

Пример в Python:
    headers = {"accept": "application/json"}
    response = requests.get("https://api.example.com/data", headers=headers)

Заголовки указывают серверу, в каком формате мы хотим получить ответ (JSON, XML, HTML) и какую информацию мы отправляем.

Пример с cURL показывает, как это выглядит в командной строке. В Python мы делаем то же самое,
но через параметр headers в requests.

В тестах заголовки используются для указания формата данных, передачи токенов авторизации и других служебных параметров.

Слайд 17 — Передача заголовков в Python через requests

Для передачи заголовков в запросах используется параметр headers, который принимает словарь с парами ключ-значение.

Пример:
    headers = {"accept": "application/json"}
    params = {"page": 1, "size": 10}
    response = requests.get("https://api.example.com/data", headers=headers, params=params)

Разбор примера:
- headers — словарь, содержащий метаданные запроса (формат ответа, авторизация, язык)
- params — параметры, передаваемые в URL после знака вопроса (?page=1&size=10)
- requests.get() — выполняет GET-запрос с нужными параметрами и заголовками

Результат: сервер получает корректный запрос с указанием формата данных, а клиент ожидает ответ в формате JSON.
Это обеспечивает правильное взаимодействие между клиентом и сервером.

В тестах мы используем заголовки для настройки запросов и проверки, что сервер правильно
обрабатывает различные форматы данных.

Слайд 18 — Тело ответа (Response Body)

Тело ответа содержит фактические данные, которые возвращает сервер. В Python есть несколько способов получить эти данные.

Как получить тело ответа:
    response = requests.get("https://api.example.com/data")
    text_data = response.text        # Получить текст ответа
    json_data = response.json()      # Преобразовать JSON в словарь Python

Методы text и json() позволяют гибко работать с разными типами ответов от API.

Разбор примера:
- json= — при отправке POST-запроса автоматически сериализует данные Python в формат JSON и устанавливает
правильные заголовки
- data= — используется, если нужно передать данные в другом формате (например, form-data)
- response.text — возвращает "сырой" ответ сервера в виде строки
- response.json() — преобразует JSON-ответ в словарь Python, с которым удобно работать

В тестах мы используем response.json() для проверки структуры и значений данных в ответе API.

Слайд 19 — Авторизация в API: Token Auth

Token Auth (авторизация по токену) — это способ безопасного доступа к закрытым API.

Для передачи токена авторизации используется заголовок Authorization:
    headers = {"Authorization": "Token your_token_here"}
    response = requests.get("https://api.example.com/protected", headers=headers)

Разбор:
- Authorization — стандартный заголовок для передачи токенов доступа
- Token your_token_here — формат, где Token указывает тип аутентификации, а your_token_here — сам токен

Такой способ используется для безопасного доступа к закрытым API, где требуется подтверждение личности пользователя.

Token Auth — это удобный и безопасный способ авторизации, при котором токен доступа передается в
заголовках каждого запроса. Сервер проверяет токен и решает, разрешить ли доступ к запрашиваемому ресурсу.

В тестах мы передаем токены в заголовках для проверки работы защищенных эндпоинтов API.

Слайд 20 — Cookies

Cookies (куки) — это небольшие фрагменты данных, которые сервер сохраняет на стороне клиента и которые
автоматически отправляются обратно на сервер при каждом запросе.

Для передачи cookies вместе с запросом можно использовать аргумент cookies,
который принимает словарь с именами и значениями cookie:
    cookies = {"session_id": "abc123", "user_pref": "dark_mode"}
    response = requests.get("https://api.example.com/data", cookies=cookies)

Разбор примера:
- cookies — словарь с cookie-парами (ключ: значение)
- Cookies позволяют сохранять сессию пользователя между запросами
- Используются для аутентификации, сохранения настроек пользователя и отслеживания состояния

С помощью аргумента cookies вы можете отправлять данные сессии и сохранять авторизацию между HTTP-запросами.
Это особенно полезно, когда API использует сессионную аутентификацию.

В тестах cookies используются для имитации работы авторизованного пользователя и проверки функциональности,
требующей сохранения сессии.

Слайд 21 — Обновление заголовков с помощью сессий

Сессии requests позволяют сохранять определенные параметры между запросами, включая cookies и заголовки.

Это удобно, если нужно выполнить несколько запросов с одинаковыми заголовками или cookies:
    session = requests.Session()
    session.headers.update({"Authorization": "Bearer ваш_токен_здесь"})
    response = session.get("https://api.example.com/endpoint1")

Разбор:
- requests.Session() создает объект сессии, который будет храниться в переменной session
- headers.update() добавляет к заголовкам новые на основе переданного словаря
- Теперь все запросы, сделанные через session, будут содержать установленный заголовок

Сессии особенно полезны в тестах, когда нужно выполнить серию запросов с одинаковыми параметрами авторизации или
другими настройками. Это избавляет от необходимости передавать
 одни и те же заголовки в каждом запросе.

Слайд 22 — Управление Cookies: Кеш и Cookies

Важно понимать разницу между кешем и cookies:

Кеш: "Не качай заново картинки, они у меня уже есть"
- Хранит временные файлы (изображения, стили, скрипты) для ускорения загрузки страниц
- Используется браузером для оптимизации производительности
- Обычно не используется напрямую в API-тестах

Cookies: "О, это тот же пользователь, он уже залогинен"
- Используются для хранения данных сессии, авторизационных токенов, предпочтений пользователя
- Автоматически отправляются на сервер при каждом запросе
- Критически важны для работы с API, требующими авторизации

В тестах мы в основном работаем с cookies, так как они необходимы для поддержания сессии и авторизации между запросами.

Слайд 23 — Работа с cookies в сессии

Cookies, полученные в ответ на запрос, автоматически сохраняются в сессии и используются при следующих запросах.

Ручное добавление cookies:
    session = requests.Session()
    session.cookies.set("session_id", "abc123")

Cookies в сессии:
    session = requests.Session()
    response = session.get("https://api.example.com/login")
    # Cookies автоматически сохраняются в session.cookies
    # И используются в следующих запросах

Сессии в requests позволяют сохранять cookies и передавать их автоматически между запросами — это делает тесты более
реалистичными и надежными. Не нужно вручную извлекать cookies из одного ответа и передавать их в следующий запрос.

В тестах это особенно полезно при проверке многошаговых сценариев, где требуется сохранить состояние между запросами.

Слайд 24 — Фикстуры в Pytest

Фикстуры — это инструмент для подготовки и очистки окружения перед и после выполнения тестов.

Они позволяют:
- подготавливать данные для тестов (создавать тестовых пользователей, настраивать окружение)
- настраивать тестовую среду (подключаться к базе данных, инициализировать API-клиент)
- освобождать ресурсы после теста (удалять тестовые данные, закрывать соединения)

Зачем нужны фикстуры:
- устраняют повторяющийся код — не нужно дублировать подготовку данных в каждом тесте
- делают тесты более читаемыми — логика подготовки вынесена в отдельные функции
- автоматизируют инициализацию и завершение тестов — Pytest сам вызывает фикстуры в нужный момент

В API-тестах фикстуры используются для создания тестовых данных, настройки сессий requests и
очистки после выполнения тестов.

Слайд 25 — Создание фикстур с помощью @pytest.fixture

Для объявления фикстуры используется декоратор @pytest.fixture, применяемый к функции.

Пример:
    @pytest.fixture
    def api_client():
        session = requests.Session()
        session.headers.update({"Authorization": "Bearer token"})
        return session

Фикстура может:
- возвращать данные для теста (объекты, словари, списки)
- выполнять предварительные настройки среды (создавать соединения, инициализировать клиенты)

Теперь любую тестовую функцию можно снабдить готовыми данными, просто указав имя фикстуры в аргументах теста.
Pytest автоматически вызовет фикстуру и передаст её результат в тест.

В API-тестах фикстуры часто используются для создания готового API-клиента с настроенными заголовками и авторизацией.

Слайд 26 — Использование фикстур в тестах

Чтобы использовать фикстуру, достаточно указать её имя в аргументах тестовой функции.

Пример:
    def test_get_users(api_client):
        response = api_client.get("https://api.example.com/users")
        assert response.status_code == 200

Как это работает:
- Pytest автоматически выполнит фикстуру перед запуском теста
- передаст её результат (в данном случае api_client) в тест
- не требует ручного импорта — Pytest ищет фикстуры в conftest.py

Фикстуры делают тесты чище, короче и понятнее, убирая необходимость повторять подготовительный код в каждом тесте.
Вместо того чтобы в каждом тесте создавать сессию и настраивать заголовки,
мы делаем это один раз в фикстуре и используем везде.

В API-тестах это особенно удобно: один раз настраиваем API-клиент в фикстуре и используем его во всех тестах.

Слайд 27 — Файл conftest.py в Pytest

conftest.py — это специальный файл, который Pytest автоматически использует для поиска и подключения фикстур.

Основные преимущества:
- Фикстуры, определённые в conftest.py, доступны во всех тестах текущего каталога и подкаталогов
- Можно создавать общие фикстуры для всего проекта
- Поддерживает вложенность фикстур — фикстура может использовать другую фикстуру

Результат: файл conftest.py делает проект структурированным, а фикстуры — переиспользуемыми и удобными для поддержки.

В API-тестах conftest.py обычно содержит фикстуры для создания API-клиентов, тестовых данных и настройки окружения.
Это позволяет использовать одни и те же фикстуры во всех тестах проекта без дублирования кода.
