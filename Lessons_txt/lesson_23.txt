# Локаторы в Playwright: конспект для урока


--- Слайд 1 ---

Локаторы в Playwright: Полное руководство для автоматизации тестирования

Здесь разберём, какие бывают локаторы в Playwright, как ими пользоваться и как писать тесты, чтобы они не падали.


--- Слайд 2 ---

Основные типы локаторов: от простых к продвинутым

Ищет по роли элемента (кнопка, поле ввода и т.д.) — так, как «видит» страницу пользователь. Обычно самый надёжный выбор.

page.get_by_role("button", name="Login")
page.get_by_role("textbox", name="Username")

ПРИМЕРЫ (
button: кнопка
textbox: поле для текста
link: ссылка
checkbox: галочка
heading: заголовок)



get_by_placeholder()
Ищет поле по подсказке внутри него (placeholder). Удобно, но подсказки могут поменять — тест сломается.

page.get_by_placeholder("Enter your username")

get_by_text()
Ищет по тому, что написано на странице. Подходит для кнопок, ссылок и всего, где есть видимый текст.

page.get_by_text("Forgot your password?")

get_by_test_id()
Ищет по атрибуту data-testid. Самый устойчивый вариант: разметку делают специально для тестов. Нужна договорённость с
разработчиками.

page.get_by_test_id("login-button")

get_by_role() – Золотой стандарт


get_by_label() – Поиск по меткам
Ищет поле по подписи рядом (label). Когда у формы нормальная разметка, тесты получаются стабильными.

page.get_by_label("Username")
page.get_by_label("Email Address")


--- Слайд 3 ---

CSS и XPath локаторы: когда стандартных недостаточно

CSS-селекторы
Используются как запасной вариант, когда семантические локаторы не подходят. Работают быстрее, но при изменении
вёрстки селектор может перестать находить элемент.

page.locator("input[name='username']")
page.locator(".login-form button")
page.locator("#submit-btn")

• Быстрое выполнение
• Знакомый синтаксис для фронтенд-разработчиков
• Хорошая поддержка в браузерах

XPath-выражения
Нужны для сложного поиска: навигация по дереву страницы, поиск по тексту с условиями. Медленнее CSS, зато гибче.

page.locator("//button[contains(text(), 'Login')]")
page.locator("//input[@type='password']")
page.locator("//div[@class='form']//button[1]")

• Навигация вверх/вниз по DOM
• Сложные текстовые условия
• Поиск по позиции элемента


--- Слайд 4 ---

Комбинирование и уточнение локаторов

Поиск внутри элемента — сначала находим контейнер (форму, блок), потом внутри него — нужный элемент. Так реже
ошибаемся.

Фильтрация — добавляем условия (например, по тексту), чтобы выбрать нужный из нескольких похожих.

Выбор по индексу — берём первый, второй и т.д. элемент из найденных. Счёт с нуля.

Примеры с слайда:
  # Найти форму, а внутри неё — кнопку
  page.locator(".oxd-form").get_by_role("button", name="Login").click()

  # Кликнуть на пункт меню с текстом "Admin"
  page.get_by_role("listitem").filter(has_text="Admin").click()

  # Взять третий элемент из найденных
  page.locator(".o\oxd-form-row").nth(1).click()


--- Слайд 5 ---

Утверждения (Assertions) с expect

expect — это проверки в Playwright. Он сам несколько раз перепроверяет условие (пока не сработает или не истечёт время).
Так тесты меньше падают из-за «ещё не успело загрузиться».

Проверка видимости

expect(locator).to_be_visible()   # элемент видим

expect(locator).to_be_hidden()    # элемент скрыт

Состояние элемента

expect(locator).to_be_enabled()   # доступен

expect(locator).to_be_disabled()  # заблокирован

Содержимое текста

expect(locator).to_have_text("exact")      # точный текст

expect(locator).to_contain_text("part")    # часть текста

Атрибуты и количество

expect(locator).to_have_attribute("type", "submit")

expect(locator).to_have_count(5)   # точное количество


--- Слайд 6 ---

Утверждения для страницы

Можно проверять не только кнопки и поля, но и саму страницу: какой у неё адрес, заголовок. Так мы убеждаемся, что
переход сработал и страница та.

Лучше проверять страницу сразу после перехода — так не будет гонок «тест уже кликает, а страница ещё не открылась».


--- Слайд 7 ---

Утверждения для страницы

После каждого перехода полезно проверить: та ли страница открылась (по URL или заголовку).

expect(page).to_have_title("OrangeHRM")
expect(page).to_have_url("https://opensource-demo.orangehrmlive.com/web/index.php/dashboard/index")

Зачем: Playwright сам подождёт загрузки, не будет «кликать где то — пока страница ещё не готова», тесты станут стабильнее.


--- Слайд 8 ---

Интеграция с Pytest

Pytest — то, в чём мы пишем тесты. Плагин pytest-playwright даёт готовые фикстуры: браузер и страница уже подготовлены.

Что за фикстуры:

page — одна вкладка на тест, после теста всё чистится.

context — как «сессия» браузера: cookies, настройки, права. Через него можно управлять окружением.

browser — сам запущенный браузер. Из него создают контексты и страницы.


ПРИМЕРЫ ФИКСТУР 
@pytest.fixture(scope="session")
def playwright_instance():
    with sync_playwright() as p:
        yield p


@pytest.fixture(scope="function")
def browser(playwright_instance):
    # browser = playwright_instance.chromium.launch(headless=False, slow_mo=50)  # slow_mo помогает видеть шаги
    browser = playwright_instance.chromium.launch(headless=True)
    yield browser
    browser.close()


@pytest.fixture(scope="function")
def context(browser):
    context = browser.new_context()
    try:
        yield context
    finally:
        context.close()


@pytest.fixture(scope="function")
def page(context: BrowserContext) -> Page:
    page = context.new_page()  # TODO подумать над мернеджером преднастройки тестов
    # page.set_viewport_size({'width': 1920, 'height': 1080})
    return page


--- Слайд 9 ---

Пример использования Playwright с Pytest

Кратко: тест заходит на страницу логина, вводит логин и пароль, жмёт «Войти» и проверяет, что открылась страница
/dashboard. То есть проверяем, что логин вообще работает.

Пример теста с слайда:
def test_login(page):
    page.goto("https://example.com/login")           # Переход на страницу логина
    page.fill("#username", "admin")                  # Ввод имени пользователя
    page.fill("#password", "12345")                  # Ввод пароля
    page.click("button[type=submit]")               # Нажатие на кнопку входа
    expect(page).to_have_url("/dashboard")          # Проверка успешной авторизации

--- Слайд 16 ---

Продвинутые техники

Явные ожидания — не ставить time.sleep(), а пользоваться встроенным ожиданием Playwright: он сам дождётся элемент
или событие. Тесты и стабильнее, и быстрее.

Автогенерация кода — можно «записать» свои действия в браузере, и Playwright выдаст готовый код. Удобно, чтобы
разобраться с локаторами и быстро набросать тест.

Примеры с слайда:

Явные ожидания (вместо time.sleep()):
  page.wait_for_selector(".success-message", state="visible")
  page.wait_for_event("domcontentloaded")

Автогенерация кода
Запишите свои действия в браузере в код автоматически.

  playwright codegen https://opensource-demo.orangehrmlive.com/

Идеально для изучения локаторов и ускорения написания тестов.

--- Слайд 17 ---

Продвинутые техники

Конфигурация через conftest.py — настраиваем браузер один раз (размер окна, игнор HTTPS и т.д.), и все тесты
работают в одном и том же окружении. Меньше сюрпризов с отображением и сертификатами.

Пример с слайда (conftest.py):
  import pytest
  @pytest.fixture(scope="session")
  def browser_context_args(browser_context_args):
      return {
          **browser_context_args,
          "viewport": {"width": 1920, "height": 1080},
          "ignore_https_errors": True
      }

--- Слайд 18 ---

Частые ошибки новичков

❌ Проблема 1: тест падает — «элемент не найден»

Решение: не подставлять time.sleep(), а использовать нормальные локаторы. Playwright сам будет ждать появления
элемента.

Пример с слайда:
  # Плохо: time.sleep(5)
  # Хорошо:
  page.get_by_role("button", name="Submit").click()
  expect(page.get_by_text("Успешно")).to_be_visible()


--- Слайд 19 ---

Частые ошибки новичков

❌ Проблема 2: тест то проходит, то нет (нестабильный)

Решение: не хранить найденный элемент в переменной надолго. Лучше каждый раз обращаться к локатору прямо перед
действием — страница могла обновиться, старый элемент уже «не тот».


--- Слайд 20 ---

Частые ошибки новичков

❌ Проблема 3: непонятно, на каком шаге и почему упало

Решение: запускать тесты с видимым браузером и замедлением (или с записью видео). Тогда видно, что именно делает
тест и где ломается.

Пример с слайда:
  pytest --headed --slowmo=1000 --video on


--- Слайд 21 ---

Рекомендации

⬤ Сначала пробуйте get_by_role и get_by_label — они чаще всего и стабильнее
⬤ К CSS и XPath прибегайте, когда по роли/метке не получается
⬤ После важных действий проверяйте результат через expect — так сразу видно, сработало ли

Если держаться этих правил, тесты будут предсказуемыми и их проще поддерживать.
