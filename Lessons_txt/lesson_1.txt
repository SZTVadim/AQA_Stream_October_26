СЛАЙД 2: Зачем нужны автоматизированные тесты
================================================================================
"Авто тесты существенно повышают эффективность тестирования ПО, 
ускоряют процесс проверки и сокращают затраты на ресурсы.

Автоматизация очень полезна для рутинных сценариев и часто повторяющихся, 
таких как регрессия, smoke-тесты, а также удобна для проверки API и базовой 
функциональности интерфейса.

Какие основные преимущества автоматизации:
- Это Быстрое выполнение большого количества тестов
- Возможность запуска тестов в любое время
- Снижение человеческих ошибок
- ну и Экономия времени и ресурсов при повторных проверках

Для тестировщика автоматизация - это инструмент, который позволяет сосредоточиться 
на более сложных и творческих задачах, с помощью нее вы делегируете рутинные проверки машине."

СЛАЙД 3: Какие кейсы стоит автоматизировать
================================================================================
"Важно понимать, что не все тесты нужно автоматизировать. Есть четкое разделение 
между ручным и автоматизированным тестированием.

Ручное тестирование подходит для:
- Сложных тестов, требующих человеческого восприятия, например, юзабилити-тесты
- Тестов, которые выполняются редко
- Тестов с небольшим объемом данных
- Уникальных случаев, которые сложно автоматизировать
- Тестирования дизайна, где нужна визуальная оценка

Автоматизация эффективна для:
- Рутинных и повторяющихся проверок, особенно регрессионных тестов
- Тестов, которые выполняются часто
- Проверки большого количества данных
- Больших объемов однотипных тестов
- Тестов, которые поддерживают автоматизацию, например, API-тесты

Поэтому важно Правильно выбрать между ручным и авто-тестированием "

СЛАЙД 4: Пирамида тестирования: баланс подходов для надежного ПО
================================================================================
"Пирамида тестирования помогает определить, какие типы автоматизированных тестов 
нужно использовать, чтобы достичь высокой надежности продукта при минимальных 
затратах.

Основание пирамиды - Unit-тесты. Они проверяют работу отдельных функций и методов. 
Это самые быстрые и многочисленные тесты - их может быть тысячи. Unit-тесты 
написаны разработчиками и проверяют изолированную функциональность.

Средний слой - Интеграционные тесты. Они проверяют взаимодействие между модулями 
и сервисами. Помогают убедиться, что части системы корректно работают вместе. 
Интеграционные тесты проверяют взаимодействие компонентов системы.

Вершина пирамиды - End-to-End (E2E) тесты. Это имитация действий реального 
пользователя. Они проверяют работу всей системы целиком - от интерфейса до базы 
данных. E2E-тесты самые медленные и дорогие, но они проверяют систему с точки 
зрения пользователя.

Как сбалансировать покрытие и скорость выполнения тестов: в идеале это когда много Unit-тестов внизу, 
меньше интеграционных в середине, и совсем немного E2E-тестов наверху.

СЛАЙД 5: Инструменты и технологии для автоматизации
================================================================================
"В целом Для авто-тестирования есть много разных инструментов и технологий. 
Мы с вами разберем основные, которые будем использовать в нашем курсе.

Python -  читаемый и универсальный язык программирования. Он идеально 
подходит для автоматизации благодаря простому синтаксису и богатой экосистеме 
библиотек.

Pytest - фреймворк для написания и запуска тестов с поддержкой фикстур, 
параметризации и интеграции с Allure. Это один из самых популярных фреймворков 
для тестирования на Python.

Requests - библиотека для работы с HTTP-запросами, отлично подходит для 
API-тестирования. С её помощью можно легко отправлять запросы к API и проверять 
ответы.

Playwright - инструмент для автоматизации браузерных end-to-end тестов, 
поддерживает все популярные браузеры. Это так скажем современная альтернатива Selenium с 
лучшей производительностью и надежностью.

Вот Эти инструменты составляют довольно мощный стек для автоматизации тестирования на разных 
уровнях - от API до UI."

СЛАЙД 6: Краткий обзор инструментов для автотестирования
================================================================================
"Здесь у нас таблица с инструментами, которые мы будем использовать. Пройдемся по каждому и разберемся, 
что к чему.

Python - это язык программирования. Читаемый, понятный, гибкий - именно на нем 
мы будем писать все наши автотесты. Это основа всего.

Pytest - это фреймворк для тестов. Он помогает быстро создавать тесты, запускать 
их, использовать фикстуры и параметризацию. Простыми словами - это структура, 
которая организует наши тесты.

Requests - это библиотека. С её помощью мы будем отправлять HTTP-запросы и 
тестировать API. То есть когда нужно проверить работу API - берем Requests.

Playwright - тоже фреймворк, но для работы с браузерами. Он автоматизирует 
браузеры и позволяет делать E2E-тесты. Хотите автоматизировать веб-интерфейс - 
сразу вспоминаем про Playwright.

В чем разница? Python - это язык, на котором мы пишем. Фреймворк - это как 
каркас, который помогает организовать код. Библиотека - это уже готовые инструменты, 
которые мы просто используем."

СЛАЙД 10: Как грамотно использовать ChatGPT с пользой для себя
================================================================================
"Как правильно работать с ChatGPT?

Задавайте вопросы по шагам. Не просите выдать вам  сразу готовое решение, разбирайте по частям.

Пример:
Вы: Как написать функцию для факториала?
ChatGPT: Показывает код.
Вы: Объясни каждую строку.
ChatGPT: Разбирает код.

Не стоит тупо копировать, лучше всего разобраться вместе с ИИ. Задавайте вопросы: 'Почему так?', 
'Что делает эта строка?', 'Можно ли сделать как то по-другому?'.

Вам нужно не получить готовый ответ, а понять и научиться решать самому."

СЛАЙД 11: Разбор ошибок и отладка
================================================================================
"ChatGPT хорошо помогает находить ошибки в коде.

Пример:
Вы: Почему программа не работает?
ChatGPT: Показывает, где ошибка.

Получили подсказку - не просто исправляйте по ней? а спрашивайте: 'Почему возникла ошибка?', 
'Как её избежать?', 'Что значит это сообщение?'.

ChatGPT кстати тоже может ошибаться. Поэтому всегда проверяйте его ответы - запускайте код, тестируйте.

Отладка - это навык. Он развивается только через практику. ChatGPT поможет вам в обучении или работе, но 
никак  не заменит ваш опыт."

СЛАЙД 13: Ограничения ChatGPT
================================================================================
"ChatGPT - помощник, но не замена вам.

Он может ошибаться. Обязательно проверяйте ответы.

Он не видит весь проект - только кусочки. Не понимает архитектуру, связи между 
модулями. Поэтому советы могут быть неполными.

Он не заменяет учителя. Учитель видит общую картину, понимает ваш уровень. ChatGPT 
- это инструмент, а не истина в последней инстанции.

Используйте ChatGPT как инструмент, а не как костыль. Если не понимаете код, который 
он дал - вернитесь к основам, изучите материал, потом используйте ChatGPT."
