================================================================================
СЛАЙД 1: Ваш первый инструментарий AQA: Git, Python и Flake8
================================================================================
Сегодня мы разберем три важных инструмента, которые нужны каждому 
автоматизатору тестирования.

Git - это система, которая помогает хранить код и работать с ним. 
Python - это язык программирования, на котором мы будем писать тесты.
Flake8 - это инструмент, который проверяет, правильно ли написан код.

Эти три инструмента - основа вашей работы. Без них не обойтись.

================================================================================
СЛАЙД 2: Git — это система контроля версий
================================================================================
Git - это как "машина времени" для вашего кода. 

Представьте, что вы написали программу, потом что-то изменили, и она 
перестала работать. С Git вы можете вернуться назад к рабочей версии.

Что умеет Git:
- Отслеживать все изменения в коде - вы видите, что и когда менялось
- Возвращаться к предыдущим версиям - если что-то сломалось, можно откатить
- Работать в команде - несколько человек могут работать над одним проектом 
  одновременно, не мешая друг другу

Git хранит всю историю вашего проекта. Это очень удобно и безопасно.

================================================================================
СЛАЙД 3: Ключевые термины Git
================================================================================
Давайте разберем основные слова, которые вы будете слышать при работе с Git.

Репозиторий - это просто хранилище вашего проекта. Там лежат все файлы 
и вся история изменений. Можно сказать, это папка проекта с "памятью".

Коммит - это снимок вашего кода в определенный момент времени. Как фотография. 
Вы сделали изменения, зафиксировали их коммитом - теперь можно вернуться к этой 
версии.

Ветка - это независимая линия разработки. Представьте, что у вас есть основная 
дорога (главная ветка) и от нее отходят боковые дороги (другие ветки). В каждой 
ветке можно работать отдельно.

Слияние - это когда вы объединяете изменения из разных веток. Например, вы 
сделали новую функцию в отдельной ветке, а потом слили ее в основную.

================================================================================
СЛАЙД 4: Создание и клонирование репозитория
================================================================================
Чтобы начать работать с Git, нужно создать репозиторий или скопировать 
существующий.

Создать новый репозиторий можно командой: git init
Эта команда создает скрытую папку .git в вашем проекте. В этой папке Git 
хранит всю историю изменений.

Если репозиторий уже существует на GitHub или GitLab, вы можете его 
скопировать командой: git clone <URL-репозитория>
Например: git clone https://github.com/username/project.git

После клонирования у вас появляется полная копия проекта со всей историей 
на вашем компьютере.

================================================================================
СЛАЙД 5: Коммит
================================================================================
Коммит - это способ сохранить текущее состояние вашего кода.

Как сделать коммит:
1. Сначала нужно добавить файлы в "зону подготовки" командой: git add <файлы>
   Или можно добавить все файлы сразу: git add .
   
2. Потом зафиксировать изменения командой: git commit -m 'сообщение'
   В сообщении напишите, что вы изменили. Например: "Добавил функцию проверки логина"

Чтобы посмотреть историю всех коммитов, используйте: git log
Это покажет вам все изменения проекта по времени - кто, когда и что менял.

================================================================================
СЛАЙД 6: Ветки (branches)
================================================================================
Ветка - это отдельная линия разработки. Зачем это нужно?

Представьте: вы работаете над новой функцией, но не хотите ломать рабочий код. 
Вы создаете новую ветку, работаете там, а когда все готово - сливаете обратно.

Создать новую ветку: git branch <имя-ветки>
Создать и сразу перейти в нее: git checkout -b <имя-ветки>
Посмотреть все ветки: git branch

Чтобы перейти на другую ветку: git checkout <имя-ветки>
Это как переключение между разными версиями проекта.

================================================================================
СЛАЙД 7: Объединение веток (merge)
================================================================================
Когда вы закончили работу в отдельной ветке, нужно объединить изменения 
с основной веткой.

Как это сделать:
1. Перейдите в целевую ветку (обычно это main): git checkout main
2. Выполните слияние: git merge <имя-другой-ветки>

Git попытается автоматически объединить изменения. Если все хорошо - 
изменения объединятся. Если Git не может понять, что делать - возникнет 
конфликт, и его нужно будет решить вручную.

================================================================================
СЛАЙД 8: Конфликт слияния
================================================================================
Конфликт возникает, когда одна и та же строка кода изменена в двух разных 
ветках. Git не знает, какую версию оставить.

Что делать при конфликте:
1. Откройте файл с конфликтом. Вы увидите пометки <<<< и >>>>
2. Посмотрите обе версии и решите, какая правильная
3. Удалите пометки и оставьте нужный код
4. Сохраните файл и зафиксируйте: 
   - git add .
   - git commit

Не бойтесь конфликтов - это нормально при командной работе. Главное - 
внимательно посмотреть, что изменилось, и выбрать правильную версию.

================================================================================
СЛАЙД 9: Pull Request (Merge Request)
================================================================================
Pull Request - это способ предложить объединить ваши изменения в основной 
проект.

Как это работает:
1. Вы работаете в своей ветке
2. Отправляете изменения на сервер (GitHub/GitLab)
3. Создаете Pull Request - это запрос на объединение

PR позволяет:
- Показать ваши изменения коллегам
- Пройти код-ревью - другие посмотрят ваш код
- Протестировать изменения перед объединением
- Обсудить изменения в комментариях

Это стандартный способ работы в команде - все изменения проходят через PR.

================================================================================
СЛАЙД 10: Отправка изменений в удаленный репозиторий
================================================================================
Когда вы сделали коммиты локально, их нужно отправить на сервер, чтобы 
другие могли их увидеть.

Отправить изменения: git push
Эта команда отправляет ваши локальные коммиты в удаленный репозиторий.

Если вы создали новую ветку и хотите отправить ее в первый раз:
git push -u origin <имя-ветки>
Флаг -u нужен только один раз, чтобы связать локальную ветку с удаленной.

После этого ваши изменения будут видны на GitHub или GitLab.

================================================================================
СЛАЙД 11: Получение изменений из удаленного репозитория
================================================================================
Когда другие люди внесли изменения в проект, вам нужно получить эти 
изменения на свой компьютер.

Для этого используется команда: git pull
Эта команда делает две вещи:
1. Скачивает изменения с сервера (git fetch)
2. Объединяет их с вашей версией (git merge)

Всегда делайте git pull перед началом работы, чтобы у вас была самая 
свежая версия проекта.

Давайте закрепим основные команды, которые вы будете использовать чаще всего:

СЛАЙД 13: Работа с ветками

СЛАЙД 15: Переменные
================================================================================
Переменная - это как коробка с ярлыком, в которой хранится информация.

Представьте коробку с надписью "name", а внутри лежит "Алиса". Это и есть 
переменная.

Пример:
name = 'Алиса'
age = 25

Здесь name и age - это переменные. В name хранится текст 'Алиса', в age - 
число 25.

Переменные нужны, чтобы хранить данные и использовать их в программе. 
Вы можете дать переменной любое имя и положить туда любое значение.

================================================================================
СЛАЙД 16: Правила и типы данных
================================================================================
Есть правила, как называть переменные:

✅ Можно начинать с буквы или подчеркивания _
✅ Можно использовать буквы, цифры и подчеркивание
❌ Нельзя начинать с цифры
❌ Нельзя использовать спецсимволы (@, $, %)

Примеры правильных имен:
user_name = 'Иван'
age_1 = 25
_count = 10

Примеры неправильных:
1user = 'Иван'  # нельзя начинать с цифры
user@name = 'Иван'  # нельзя использовать @

Следуйте этим правилам, и ваш код будет понятным и правильным.

================================================================================
СЛАЙД 17: Присваивание и память
================================================================================
В Python переменные работают по ссылке. Это значит, что если две переменные 
указывают на один объект, изменения в одной могут отразиться на другой.

Простыми словами: если вы создали список и присвоили его двум переменным, 
то изменения в одной переменной будут видны и в другой.

Это важно понимать, когда работаете со списками и словарями. Для простых 
типов (числа, строки) это не так критично, потому что они не изменяются.

Главное - помните, что присваивание в Python работает не как копирование, 
а как создание ссылки на объект.

================================================================================
СЛАЙД 18: Динамическая типизация и проверка типа
================================================================================
Python - язык с динамической типизацией. Это значит, что вам не нужно 
заранее говорить, какого типа будет переменная.

Python сам определяет тип по значению:
x = 5  # Python понимает, что это число
y = 'привет'  # Python понимает, что это строка
z = True  # Python понимает, что это булево значение

Чтобы проверить тип переменной, используйте функцию type():
type(x)  # покажет, что это int (число)

Это удобно - не нужно думать о типах заранее. Python все сделает сам.

================================================================================
СЛАЙД 19: Константы в Python
================================================================================
Константа - это переменная, значение которой не должно меняться.

В Python нет специального типа "константа", но есть соглашение: если 
переменная написана ЗАГЛАВНЫМИ буквами - это константа, ее нельзя менять.

Пример:
MAX_USERS = 100
API_URL = 'https://api.example.com'

Если вы видите переменную в верхнем регистре - это сигнал: "это значение 
не должно изменяться". Следуйте этому правилу, и ваш код будет понятнее.

================================================================================
СЛАЙД 20: Базовый синтаксис — операторы в Python (Арифметические)
================================================================================
Операторы - это символы, которые выполняют действия с числами.

Арифметические операторы:
+ сложение: 2 + 3 = 5
- вычитание: 5 - 2 = 3
* умножение: 2 * 3 = 6
/ деление: 6 / 2 = 3
** возведение в степень: 2 ** 3 = 8 (два в степени три)
// деление без остатка: 7 // 2 = 3 (целая часть)
% остаток от деления: 7 % 2 = 1 (остаток)

Это как калькулятор - вы используете эти операторы для вычислений в коде.

================================================================================
СЛАЙД 21: Базовый синтаксис — операторы в Python (Сравнения)
================================================================================
Операторы сравнения проверяют, больше ли одно число другого, равны ли они, и т.д.

Результат всегда True (правда) или False (ложь).

< меньше: 2 < 5 вернет True
> больше: 5 > 2 вернет True
<= меньше или равно: 3 <= 3 вернет True
>= больше или равно: 5 >= 3 вернет True
== равно: 5 == 5 вернет True
!= не равно: 5 != 3 вернет True

Эти операторы используются в условиях: "если это больше того, то сделай то-то".

================================================================================
СЛАЙД 22: Базовый синтаксис — операторы в Python (Присваивания)
================================================================================
Операторы присваивания записывают значение в переменную.

= обычное присваивание: x = 5 (положить 5 в переменную x)
+= сложение и присваивание: x += 3 (то же самое, что x = x + 3)
-= вычитание и присваивание: x -= 2 (то же самое, что x = x - 2)

Это удобные сокращения. Вместо писать x = x + 1, можно написать x += 1.
Код становится короче и понятнее.

================================================================================
СЛАЙД 23: Базовый синтаксис — операторы в Python (Логические и принадлежности)
================================================================================
Логические операторы объединяют несколько условий:

and (И): оба условия должны быть True
or (ИЛИ): хотя бы одно условие должно быть True
not (НЕ): меняет True на False и наоборот

Пример: если возраст больше 18 И есть паспорт - тогда можно.

Операторы принадлежности проверяют, есть ли элемент в списке или строке:

in (В): проверяет, есть ли элемент в последовательности
not in (НЕ В): проверяет, нет ли элемента

Пример: 'a' in 'apple' вернет True, потому что буква 'a' есть в слове 'apple'.

================================================================================
СЛАЙД 24: Базовый синтаксис — операторы в Python (Тождественности и битовые)
================================================================================
Операторы тождественности проверяют, указывают ли переменные на один объект:

is (это): проверяет, одна ли это переменная
is not (это не): проверяет, разные ли это переменные

Это не то же самое, что ==. == проверяет значения, is проверяет, один ли это объект.

Битовые операторы работают с числами на уровне битов. Они редко нужны в 
автоматизации, но знать о них полезно:

& бинарное И
| бинарное ИЛИ

Для начала вам достаточно знать про is и is not. Остальное придет с опытом.

СЛАЙД 25: Структура программы на Python
================================================================================
Программа на Python - это последовательность строк кода, которые выполняются 
сверху вниз.

Отступы очень важны! В Python отступы определяют, какие строки принадлежат 
к одному блоку. Например, код внутри if должен быть с отступом.

Комментарии помогают объяснить, что делает код:
# Однострочный комментарий
'''Многострочный комментарий'''

Комментарии не выполняются, но помогают понять код. Используйте их, чтобы 
объяснить сложные места.

================================================================================
СЛАЙД 26: PEP 8 — стандарт чистого кода в Python
================================================================================
PEP 8 - это официальное руководство, как писать код на Python.

Зачем это нужно:
- Чтобы код был читаемым и понятным
- Чтобы все писали в одном стиле
- Чтобы код было легко поддерживать

PEP 8 создан Python Software Foundation и используется во всех крупных 
проектах. Если вы хотите работать профессионально - следуйте PEP 8.

Это не просто "хорошо бы", это стандарт индустрии. Код, написанный по PEP 8, 
легче читать и понимать.

================================================================================
СЛАЙД 27: Основные правила PEP 8
================================================================================
Основные правила, которые нужно запомнить:

⬤ Отступы - 4 пробела (не табы!)
⬤ Длина строки - до 79 символов (можно настроить до 120)
⬤ Имена переменных - snake_case (user_name, не userName)
⬤ Имена классов - CamelCase (UserProfile, не user_profile)
⬤ Пробелы вокруг операторов: x = y + 2 (не x=y+2)
⬤ Пустые строки между функциями и классами
⬤ Импорты - в начале файла, по группам

Следуя этим правилам, вы сделаете код аккуратным и профессиональным. 
Коллеги скажут вам спасибо.

СЛАЙД 28: Пример форматирования кода
================================================================================
Вот пример, как НЕ надо и как НАДО писать код:

❌ Неправильно:
def test(x,y):
if x>y:
print("больше")
return x+y

✅ Правильно:
def test(x, y):
    if x > y:
        print("больше")
    return x + y

Видите разницу? Правильный код:
- Имеет отступы
- Имеет пробелы вокруг операторов
- Легко читается

Код становится понятнее не только вам, но и коллегам при ревью кода.

СЛАЙД 29: Flake8 — инструмент проверки стиля
================================================================================
Flake8 - это инструмент, который автоматически проверяет ваш код на 
соответствие PEP 8.

Что проверяет Flake8:
- Длину строк
- Пробелы и отступы
- Неиспользуемые переменные
- Дублирование импортов

Установить: pip install flake8
Проверить один файл: flake8 my_script.py
Проверить весь проект: flake8 .

Flake8 найдет все проблемы со стилем и покажет, что нужно исправить. 
Используйте его перед каждым коммитом.

================================================================================
СЛАЙД 30: Настройка длины строки
================================================================================
По умолчанию Flake8 требует, чтобы строка была не длиннее 79 символов. 
Но в современных проектах часто разрешают до 120 символов.

Как настроить:
1. Командой: flake8 --max-line-length=120
2. Или в файле .flake8:
   [flake8]
   max-line-length = 120

Создайте файл .flake8 в корне проекта, и Flake8 будет использовать ваши 
настройки автоматически.
