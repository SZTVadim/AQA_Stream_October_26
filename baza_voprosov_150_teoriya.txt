========== lesson_1.txt (вопросы 1–11) ==========

1. Какие задачи решает автоматизация тестирования?
Ускоряет проверки, снижает рутину и человеческие ошибки, экономит время на повторных прогонах.

2. Для каких сценариев автоматизация особенно полезна?
Регрессия, smoke, частые повторы, большие объёмы однотипных проверок, API и базовая проверка UI.



4. Что лежит в основании пирамиды тестирования и кто обычно пишет такие тесты?
Unit-тесты — быстрые, многочисленные; чаще разработчики, изолированная логика.



7. Как выгляждит пирамида тестирования?
unit test, api, ui 

8. Какую роль в стеке курса играет pytest?
Фреймворк для написания и запуска тестов: фикстуры, параметризация, отчёты.


10. В чём разница между языком программирования, фреймворком и библиотекой по смыслу урока?
Язык — на чём пишем; фреймворк — каркас организации тестов; библиотека — готовые функции для задач.

11. Какое главное правило использования ChatGPT при обучении по уроку?
Помогает объяснять и ускорять, но не заменяет понимание; нельзя только копировать без разбора.


========== lesson_2.txt (вопросы 12–24) ==========

12. Что такое CI/CD в целом?
Автоматизация сборки, тестирования и доставки/развёртывания при изменениях кода.

13. Чем CI отличается от CD?
CI — непрерывная интеграция: сборка и тесты; CD — доставка или развёртывание в среды после проверок.

14. Что такое pipeline?
Последовательность автоматических шагов от кода до деплоя.

15. Какие три основных этапа пайплайна названы в уроке?
Сборка, тестирование, развёртывание.

16. Что такое артефакты сборки?
Готовые результаты сборки для следующих шагов.

17. Зачем нужен runner в CI/CD?
Агент, который выполняет jobs пайплайна на машине.

18. Для чего ограничивают пайплайн определёнными ветками?
Разные политики: полный прогон на main, лёгкие проверки на feature-ветках.

19. Чем dev, staging и prod отличаются по назначению?
Dev — разработка; staging — проверка перед релизом; prod — реальные пользователи.

20. В чём разница Docker-образа и контейнера?
Образ — шаблон; контейнер — запущенный экземпляр приложения из образа.

21. Зачем Dockerfile?
Текстовое описание того, из чего собирается образ и что запускается.

22. Зачем Docker Compose?
Запуск нескольких связанных сервисов одной конфигурацией.

23. Почему автоматизатору полезно знать Kubernetes?
Тесты и стенды часто в кластере; самостоятельность с логами и pod.

24. Зачем в Kubernetes Service, если Pod’ы пересоздаются?
Стабильная точка доступа и балансировка между подами.


========== lesson_4.txt (вопросы 25–35) ==========

25. Зачем система контроля версий Git в работе AQA?
История изменений, откат, совместная работа без потери кода.

26. Что такое коммит в терминах Git?
Снимок состояния проекта в точке времени с сообщением.

27. Зачем ветки в Git?
Изолированная разработка фич без поломки основной линии.

28. Когда возникает конфликт слияния?
Одни и те же строки изменены в разных ветках; Git не может выбрать версию автоматически.

29. Зачем Pull Request?
Показать изменения, код-ревью, обсуждение и контроль перед слиянием.

30. Что делает git pull?
Скачивает изменения с удалённого репозитория и вливает их в текущую ветку.

31. Что такое динамическая типизация в Python?
Тип переменной выводится из значения, объявлять тип заранее не требуется.

32. Зачем PEP 8?
Единый стиль кода: читаемость, поддержка, профессиональный стандарт.

33. Для чего Flake8?
Автоматическая проверка стиля и простых проблем в духе PEP 8.

34. Почему важна настройка максимальной длины строки для линтера?
Согласовать правила команды.

35. Как в уроке описывают присваивание для изменяемых объектов?
Часто это ссылка на один объект; два имени могут видеть одни и те же данные.


========== lesson_5-9.txt (вопросы 36–57) ==========

36. Почему важно понимать типы данных в Python?
От типа зависят допустимые операции и типичные ошибки вроде неверных операций.

37. Что значит, что строки в Python неизменяемы?
Прямо «поменять» символ в существующей строке нельзя — создаётся новая строка.

38. Почему методы регистра у строк не меняют исходную строку?
Возвращают новую строку; без присваивания исходник остаётся прежним.

39. Зачем методы удаления пробелов по краям строки?
Корректные сравнения и ввод пользователя без «невидимых» отличий.

40. В чём разница по смыслу между split и join?
Split режет строку в список; join собирает список строк в одну с разделителем.

41. Как replace ведёт себя с вхождениями подстроки?
Заменяет все вхождения; регистр важен.

42. Чем find отличается от index при отсутствии подстроки?
find возвращает «не найдено» без исключения; index бросает ошибку.

43. Почему порядок при распаковке множества ненадёжен?
Множество неупорядочено; порядок элементов не гарантирован.

44. Какие свойства ключей в словаре по уроку?
Ключи уникальны; значения любого типа; с версии 3.7+ сохраняется порядок вставки.

45. Чем отличается фильтрующий if в генераторе списка от if-else внутри выражения?
if отбрасывает элементы; if-else преобразует каждый элемент.

46. Чем множество удобно для проверки «есть ли элемент»?
Обычно быстрая проверка принадлежности.

47. Что произойдёт с дубликатами при создании множества из списка?
Дубликаты исчезнут — останутся уникальные значения.

48. Чем кортеж принципиально отличается от списка?
Кортеж неизменяем после создания.

49. Чем sort у списка отличается от встроенной sorted по эффекту на исходные данные?
sort меняет список на месте; sorted возвращает новый отсортированный список.

50. В чём разница между присваиванием списка и его копией?
Присваивание даёт общую ссылку; copy или срез создают отдельный список.

51. Зачем генераторы списков вместо длинных циклов?
Компактнее и часто читабельнее для преобразований и фильтрации.

52. Что даёт метод update при объединении словарей?
Вливает пары из другого словаря; при совпадении ключей побеждает значение из «второго».

53. Чем remove отличается от discard при удалении из множества?
remove ошибается, если элемента нет; discard безопасно ничего не делает.

54. Что делает pop у множества без выбора элемента?
Удаляет и возвращает произвольный элемент.

55. Зачем тройные кавычки в Python кроме многострочного текста?
Стандартные docstrings для документации функций.

56. Для чего оператор in с последовательностями?
Проверка принадлежности элемента.

57. Что такое list comprehension в двух словах?
Краткая форма создания списка из итерируемого с опциональным условием.


========== lesson_13.txt (вопросы 58–66) ==========

58. Что такое распаковка данных в Python?
Присвоение нескольким переменным значений из коллекции за один шаг.

59. Зачем звёздочка при распаковке списка?
Собирает «остаток» элементов в отдельный список.

60. Как распаковать первый, середину и последний элемент одной конструкцией?
Первая переменная, звёздочка с именем для середины, последняя переменная.

61. Зачем метод items() при переборе словаря?
Даёт пары ключ–значение для одновременной распаковки в цикле.

62. Для чего оператор двойной звёздочки при слиянии словарей?
Объединяет словари; при конфликте ключей берётся значение из последнего участника слияния.

63. Зачем распаковывать коллекцию в аргументы функции?
Передать элементы как отдельные позиционные или именованные аргументы.

64. Что собирает конструкция с одной звёздочкой в параметрах функции?
Произвольное число позиционных аргументов в кортеж.

65. Что собирает конструкция с двумя звёздочками в параметрах функции?
Произвольные именованные аргументы в словарь.

66. Работает ли распаковка кортежа иначе, чем списка, по сути урока?
Та же логика; отличие в неизменяемости самого кортежа.


========== lesson_14.txt (вопросы 67–77) ==========

67. Зачем функции в программе по уроку?
Повторное использование логики и аккуратная структура.

68. Чем параметр отличается от аргумента?
Параметр — место в объявлении; аргумент — фактическое значение при вызове.

69. Что делает return в функции?
Завершает функцию и отдаёт результат; код после него в этой ветке не выполняется.

70. Какие способы передачи аргументов перечислены в уроке?
Позиционные, именованные, значения по умолчанию, переменное число через специальный синтаксис.

71. Зачем условия if в программе?
Ветвление: разное поведение при разных данных.

72. Когда использовать elif вместо нескольких if подряд?
Несколько взаимоисключающих вариантов — выполнится только первая подходящая ветка.

73. Как while отличается от for по идее урока?
While крутится, пока условие истинно; for перебирает элементы коллекции.

74. Почему в while важно менять переменные внутри цикла?
Иначе условие никогда не станет ложным — бесконечный цикл.

75. Когда уместен match/case вместо длинной цепочки if?
Когда выбираем из набора конкретных значений, а не сравниваем диапазоны.

76. Что такое range и каков нюанс правой границы?
Последовательность чисел; конечное значение не включается.

77. Когда lambda предпочтительна, а когда обычная функция def?
Lambda — для очень простого однострочного выражения; def — для сложной логики и читаемости.


========== lesson_15.txt (вопросы 78–86) ==========

78. Зачем модуль datetime автоматизатору?
Даты в данных, логи, длительности, таймауты, сравнение времён.

79. Нужно ли отдельно устанавливать datetime?
Нет, это стандартная библиотека Python.

80. Что хранит класс date, а что time, по уроку?
date — только дата; time — только время суток без привязки к календарной дате.

81. Для чего класс timedelta?
Выражать разницу и сдвиги во времени.

82. Какой класс чаще всего используют, когда нужны и дата, и время вместе?
datetime.

83. Что такое timestamp и зачем он в тестах и интеграциях?
Секунды от эпохи; удобно сравнивать и обмениваться с API и БД.

84. Как измерить длительность операции с помощью datetime?
Зафиксировать время до и после, вычесть — получить интервал.

85. Зачем сравнивать даты в тестах?
Проверять корректность времени создания событий, сроков и т.п.

86. Какие способы импорта модуля datetime упоминаются в уроке?
Импорт имён из модуля, импорт всего модуля, импорт с псевдонимом.

Объединить данные и поведение, упростить повторное использование одного шаблона.

88. Что такое класс и что такое объект простыми словами?
Класс — описание; объект — конкретный экземпляр с своими значениями полей.

Инициализация объекта при создании: начальные поля и подготовка.

Функции, привязанные к объекту и работающие с его данными.

Да; у каждого свои значения атрибутов.

Автоматически при создании экземпляра, без ручного вызова.

Ссылка на текущий объект, с которым работает метод.

95. Что было бы без конструктора по смыслу урока?
Пришлось бы вручную настраивать каждый объект после создания — легче ошибиться.

========== lesson_18-19.txt (вопросы 105–124) ==========

105. Что даёт ООП тестировщику по этому уроку?
Структура кода, переиспользование, модели пользователей и утилит для API/БД.

106. Назовите четыре столпа ООП из урока.
Инкапсуляция, наследование, полиморфизм, абстракция.

Скрытие внутренностей объекта и доступ через ограниченный интерфейс методов.

108. Что такое наследование?
Новый класс расширяет или специализирует существующий, переиспользуя поведение.

109. Что такое полиморфизм в контексте урока?
Одинаковые вызовы для разных типов объектов с разной реализацией.

110. Что такое абстракция в ООП?
Выделение существенного интерфейса без деталей реализации.

111. Зачем абстрактный метод в базовом классе?
Обязать потомков реализовать поведение, не фиксируя его в родителе.

112. Можно ли создать экземпляр абстрактного класса с нереализованными абстрактными методами?
Нет, это должно приводить к ошибке на этапе создания объекта.

113. Зачем в Python модуль abc и декоратор abstractmethod?
Формализовать абстрактные базовые классы и обязательные методы.

114. Как в уроке обозначают «приватные» поля?
Соглашения с подчёркиваниями; доступ предпочтительно через методы.

115. Зачем инкапсуляция в тестах?
Защита данных от некорректного изменения и сокрытие сложной логики.

116. Что генерирует dataclass автоматически по уроку?
Как минимум конструктор, представление и сравнение; опционально хеширование.

117. Плюсы dataclass для тестовых структур данных?
Меньше шаблонного кода, явный список полей, быстрее заводить модели данных.

118. Что такое итератор в Python?
Объект с методами перебора: выдаёт элементы по одному до исчерпания.

119. Что сигнализирует StopIteration?
Элементы итератора закончились.

120. Чем генератор отличается от обычной функции по выдаче значений?
Порционная выдача через yield с сохранением состояния; экономия памяти.

121. Где в тестах полезны генераторы по уроку?
Большие объёмы тестовых данных, выдача порциями, стримоподобные сценарии.

122. Зачем обычный метод в абстрактном классе рядом с абстрактным?
Общая реализация, которую можно наследовать или переопределять по желанию.

123. Как абстракция соотносится с «пультом» в аналогии урока?
Пользователь жмёт кнопки интерфейса, не зная внутренней схемы устройства.

124. Зачем сравнение объектов через сгенерированный метод равенства в dataclass?
Удобно сравнивать тестовые структуры по содержимому полей.


========== lesson_20.txt (вопросы 125–135) ==========

Разделение кода, повторное использование утилит, данных и клиентов.

Когда нужны только несколько функций — короче и яснее в теле теста.

Поведение интерфейса сервера без UI: запросы, ответы, логика.

Скорость, устойчивость к смене вёрстки, ранний старт, глубина проверки логики.

Чтение данных без изменения состояния ресурса.

130. Чем PUT отличается от PATCH по смыслу?
PUT — полная замена ресурса; PATCH — частичное обновление полей.

Успех; ошибка клиента; ошибка сервера.

132. Зачем библиотека requests в Python-тестах?
Удобный слой над HTTP для запросов и разбора ответов.

133. Что передают заголовки запроса и ответа?
Метаданные: формат, авторизация, язык и т.д.

134. Чем params отличается от тела запроса по назначению?
Params идут в строку запроса URL; тело — для полезной нагрузки.

135. Зачем объект Session в requests?
Переиспользование cookies и заголовков между последовательными запросами.


========== lesson_23.txt (вопросы 136–150) ==========

136. Что такое локатор в Playwright?
Способ найти элемент на странице для действия или проверки.

137. Почему поиск по роли считается предпочтительным в уроке?
Отражает то, как пользователь воспринимает интерфейс.

138. В чём риск локатора по placeholder?
Текст подсказки могут изменить — тест хрупкий.

139. Зачем атрибут вроде data-testid и что нужно команде?
Стабильный поиск; нужна договорённость с разработкой.

140. Когда в уроке оправданы CSS и XPath?
Когда семантические способы не подходят; CSS быстрее, XPath гибче для сложного DOM.

141. Зачем сужать поиск через контейнер, а потом искать внутри?
Меньше шанс кликнуть не тот элемент среди похожих.

142. Что даёт фильтрация локаторов по условию?
Выбрать один элемент из нескольких совпадений.

143. Зачем иногда брать элемент по порядковому номеру среди найденных?
Когда однозначно выделить иначе нельзя.

144. Как устроены автоповторы в expect?
Условие проверяется до успеха или таймаута — меньше гонок при загрузке.

145. Зачем проверять URL или заголовок страницы после перехода?
Подтвердить, что открылась нужная страница, и дать Playwright дождаться состояния.

146. Что дают фикстуры page, context и browser в связке pytest-playwright?
Страница на тест, сессия браузера с настройками, сам браузер как фабрика контекстов.

147. Зачем в уроке упоминают автогенерацию действий в браузере?
Быстро набросать сценарий и увидеть рабочие локаторы.

148. Зачем выносить настройки контекста браузера в общий конфиг тестов?
Единый viewport, работа с HTTPS и др. для всех тестов без дублирования.

149. Какие три типичные ошибки новичков и подходы из урока?
Не злоупотреблять паузами; не кешировать «устаревшие» элементы; отлаживать с видимым браузером и замедлением или видео.

150. Что рекомендуют делать после важных действий в сценарии по итогам урока?
Проверять результат через expect, чтобы сразу видеть успех или провал шага.
